## 已验证的计算

1. **速度、路程近似与停车。** `Motion` 从初态建立一次状态点，每个物理子步加入一次；相邻控制记录的初态严格等于上一末态，`final` 严格等于最后样本。实际物理间隔必须为保存的 0.01 秒，允许的 `1e-9` 时间误差仅处理浮点表示，不补帧。速度使用获准运动学模型的 body `vx`（`vy=0`），梯形和为 `sum((v[k]+v[k+1])*Δt/2)`，单位米；除以实际观察时长为平均速度，单位米/秒。该积分是采样路程近似，不是全局 x 位移。初末速度均参与极值，末点不再额外占用一个时间区间。
2. **继承停车定义。** 阈值来自源快照 `configs/phase2.json` 的 `stopped_speed_tolerance_mps=1e-6`，没有另行调参。对每个区间使用左端速度 `v[k] <= 1e-6` 累加 `Δt`，阈值包含等号。它是网格上的停车时间定义，不能视为对连续时间跨阈值时刻的精确定位。
3. **实际加速度和 jerk。** 初态只用冻结 `KinematicModel.observe` 的标量公式：限幅后的实际纵向加速度在零速负向/最高速正向投影为零；横向加速度为 `vx² tan(steering)/wheelbase`。后续直接读取保存的实际 diagnostics。纵向 jerk 使用实际加速度相邻差分除以实际时间间隔，包括初态至第一子步以及跨控制记录边界。横向指标为实际横向加速度绝对值峰值，没有将控制命令变化当作实际 jerk。
4. **完整窗口与失败前缀。** 完成状态必须有全部时间区间。缺帧、重复/不连续时间、坏末态、不完整的 completed 物理记录均拒绝。失败或不完整案例的 `full_window` 为 null；可用 `observed_window` 保留实际完整物理前缀且不补尾。若一个 failed 同步记录已有所有车辆完整物理积分，该步可以计入观察物理前缀；只有部分车辆积分时整段尾步不纳入共同前缀，并保留失败信息。CSV 的完整窗口数值列对失败案例留空。
5. **原始覆盖与 C 的边界。** 原始几何检测的并集比例和最大单组比例分别按控制采样左阶梯积分；并集可能由互不连通的小组构成，二者都包含未达持续确认条件的几何组。它们没有替换预登记 `[formed,end)` 的持续确认最大组 C，没有倒填确认前区间，也不参与方法选择。最后检测帧可贡献瞬时最大值，但没有额外持续时长。
6. **0.005 秒结果。** `refinement_summary` 对已经保存的命令重积分轨迹计算实际纵向 jerk；检查步长、初末连续性、子步数及完整区间数。`jerk_passed` 与封存舒适阈值比较，不能解释成重新运行闭环控制器的半采样结果，也不证明采样点间连续 jerk 受限。

## A 的核验范围与报告限制

A 摘要含 21 个完整变体、111 条车辆统计，其中 103 条受控车辆具有源包标准指标且全部与保存子步复算值匹配；另 8 条外生车辆明确标记标准指标未记录。外生车辆的运动描述不能自动继承受控车的标准验收结果。源摘要仍保留科学未通过与工程通过的分别状态，离线脚本执行成功不改变它们。

以下限制须在主报告保留：

- `verify_source` 核验 manifest 列出的文件及代码/输入快照内部哈希；它不验证整个源目录的精确文件集合，不独立证明来源身份、预登记完整 case 矩阵、代码语义或物理重放。外层摘要只分析顶层 validation 已列出且具有必要 metadata/trace/validation/detection 的案例；缺必要派生文件会失败，不能用该脚本替代全矩阵缺项统计或给未开始案例补零。与标准源包绑定重放合用才符合报告所述来源条件。
- failed 同步步的完整物理样本可能比成功检测帧多一个区间。因此失败案例的运动 `observed_duration_s` 与 `raw_local_coverage.observed_window.duration_s` 可以不同，应各自标明窗口；不能直接把两个前缀指标当共同完整窗口进行方法差值比较。
- 0.01 秒速度/停车和 0.005 秒 jerk 都是保存网格上的描述；极值不能排除更细时刻的峰值。外层脚本不运行控制器，不构成额外线上控制、安全证明或串行稳定证据。

下一入口：主报告可引用本次通过的运动统计核验及 A 的已保存摘要，并与标准整包重放绑定共同列证据；对其余正式包，仅在包结束、必要派生文件齐全并完成绑定后按同一冻结脚本生成摘要。正式比较继续遵守预登记及 heldout 汇总的共同完整观察窗口/null 规则，不由本报告选择方法或更改参数。
