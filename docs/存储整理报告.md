## 3. GitHub 与本地版本怎样配合

在线仓库是 [32780542/yanjiu1](https://github.com/32780542/yanjiu1)。一次代码调整形成一次 Git 提交，并推送到该仓库的 `main`。需要回到旧代码时，按提交查看或切换，无需额外复制整个项目目录作为版本。

本地 `.git` 保存的是 Git 对象，当前只有约 3.2 MiB。保留它可以继续比较、提交和推送。用 GitHub 管理版本，重点是停止手工复制整份项目，而不是去掉这几 MiB 的正常 Git 元数据。

大型实验轨迹适合压缩归档后放在发布附件或专用数据存储中，源码文档登记它们的地址、工况、摘要和用途。GitHub 普通仓库会对超过 50 MiB 的文件提示，并阻止超过 100 MiB 的文件进入普通 Git；发布附件是官方给出的另一种分发方式。参见 [GitHub 大文件说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)。

建议日常采用以下习惯：

1. 源码修改直接使用 Git 提交，提交信息写清规则或工程变化。
2. 每批实验保存参数、seed、结果摘要和唯一运行编号。
3. 常用实验保留本地压缩轨迹，方便继续定位问题。
4. 已完成批次归档到线上数据位置后，在文档登记地址和 SHA-256，再按研究需要安排本地保留范围。
5. 同一算法、同一工况重复跑出的临时比较材料按批次管理，避免复制整个工程。
