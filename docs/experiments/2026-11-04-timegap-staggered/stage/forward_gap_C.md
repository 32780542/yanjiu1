# C：前向虚拟合流队列与真实编队空位

候选源为`tmp/staggered_bottleneck/candidates/20261104_forward_gap_C200/native_rules.py`及对应`C300`，各311行，二者仅`ROAD_PREVIEW`不同。保留冻结A的NOA、车辆物理、安全、h=0.85和mutual软相位图；没有修改A/B/生产源，没有运行仿真。

## 直接规则

1. **主前驱严格在前。** 从前200 m全部可见实车中选择实际本车道最近前车，形成目标为F−D(v)。NOA仍使用原50 m普通跟驰；C的200 m是主动编队闭孔反馈，用来处理仍可见但超过50 m的大孔。没有持久三车角色，也不按前驱道色重新染色。
2. **只接收当前可执行的合流。** 知道道路缩减或看到实际向内横移后，道1可把严格在前的道2车作为虚拟前驱；必须先以当前位置及1 s外推验证该车进入道1的原8 m前后走廊。已停末道车在998.5 m、接收车在995 m时，这个虚拟关系被拒绝；接收车继续正常前进，实际通过后由新的后车接续。
3. **一层公开几何接续。** 道0可把严格在前的道1车作为虚拟前驱，条件是该道1车又受其严格前方ending车挤压，而且ending→1、middle→0两条当前走廊都可执行。已观察到middle真实向0横移时也可提前接收。该两层让行可能把扰动向上游扩展，是C本身待实测的假设。
4. **真实空位才补。** 当前本车受实际/可执行虚拟前车挤压时，检查相邻道实际前车F后的x*=F−D_entry。目标点前后均须保留完整D_entry，并通过当前及1 s相对速度检查；不取gap中点，不统计车数或未来负荷。新位置要比本车当前CTH目标更前；正接收ending的道1车可采用相等目标，以容许向道0分流。一次只保持一个实际前车锚点和目标道，失效即释放，不维护等待队列。实际横移仍须原`_clear`走廊通过，可先纵向调整再提交横移。
5. **ending只做2→1。** 一位本车自身记忆记录已启动必要退道，完成后不再因邻车颜色追到道0。没有邻车pending、角色或私有stage输入。

接入几何D_entry=max(5.5+0.85v, 2×8 m)，保证半pitch至少8 m；16来自原横移走廊，不按交通表现调节。仅在局部仍有ending车、实际横移或准备的空位接入时采用；ending及横移消失后，普通形成CTH回到原D(v)，不永久扩大低速间距。接入期间不叠加软相位，结束后恢复原mutual相位反馈。实际本车道前车的200 m跟驰始终限制C的速度，安全包装与NOA共用。

## 自身记忆

沿用`lane_target`保持本次准备/执行道，`front`只关联该空位的实际前车，`transforming`记录本车已开始道路变换；只增加`merged_from_ending`一位本车退道历史。主引用每次都重新验证严格前向，历史关联落到本车后方时不能继续压低本车速度。
