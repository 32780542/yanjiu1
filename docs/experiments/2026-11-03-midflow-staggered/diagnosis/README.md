## 代码事实

- `native_rules.py::_decide`在`x>=drop_x-360=640m`进入准备区。终止道2立刻用`_merge_target`的实际lane1前后车求中点/单侧目标；`_clear`通过就请求2→1，未通过则独立追踪当前gap。NOA与S使用同一个准备距离、必要合流分支和安全走廊。
- S全程用实际相邻道互选phase形成交错；640m后继续道的`_fill`按两道处理。必要合流及执行分支用`_join_speed`覆盖先前`_following`速度，因此终止车合流纵向目标来自gap，并非继续服从交错phase。
- 接收道车辆没有“为这个即将并入的实际车提前遵循CTH”的纵向拓扑。`_mandatory_priority`只防止lane0→1的自由补位侵占终止车走廊；现有CTH/停止安全在实际车身占道后响应。
- `_clear`允许当前和1秒速度外推都达到8m前端位置差；巡航真实CTH却要求`5.5+0.8506944444v=30m`。8m保障横移走廊可用，并不保证合流后的纵向CTH无需重组。SUMO会继续检查实际gap和执行变道。
- 原生`lane_change`事件是车道索引翻转的横移中点。`lane_completion`另要求实际目标车道、横向静止和中心误差<.05m；不能把中点当横移开始或完成。原生`requested_s`为最近一次changeLane提交，亦不等同真实横移开始。

## 最小更新方向

优先只试一个拓扑过渡：继续道1只对有限局部可见、处于准备区lane2的实际车辆、且自己恰为其目标道实际紧邻后车时，用相同CTH提前响应。保留更近真实前车的约束；只用实际位置速度和公开道路信息，不读取对方私有gap/stage，不建立helper、全局槽或等待链。

此方法与旧C的“选head+helper并让helper换lane0”不同。若加入，投影CTH应进入既有`_following`的CTH优先逻辑，避免phase仍把本车当自由head而与新CTH持续相抵。不要在并排或后方车辆上虚构正前车间距。

已登记V1的实际patch做到了原CTH与phase优先衔接。额外限制是本车也必须`preparing`，即接收车自己已过640m：典型终止车x642、接收车在其后16m≈626时不会启用，等接收车到640时终止车可能早已实际占lane1。因此V1若无收益，只能否定这一具体本车区域限定实现，不能概括否定提前纵向拓扑的假设。若需第二个独立最小方向，可单独解除本车区域门槛，仍仅对实际可见且已经处于道路准备区的终止车响应；不得改写已启动V1源或协议。此判断写于候选结果产生前。

可检验假设是减少640–800接收道的间距压缩与制动，并减少完整系统时间；若只是增加提前让行时间或更早完成位置，而总时延/燃油变坏，应如实拒绝。现阶段无需叠加第二个特判。

另一个可以独立研究的方向是未来资源图的负荷均衡，不与投影CTH叠加。现`_fill(preparing,lanes=2)`的members、window、counts、anchor和full只看真实lane0/1，lane2即将流入1的负荷被遗漏；当前01完整层的保护也不能代表未来接收容量足够。仅把counts改为`min(lane,1)`并不闭合：原full/candidates仍冻结成形中道车，centers也仍由原01 anchor定，可能没有实际补位机会。

清晰的统一定义应是未来资源映射`π(0)=0, π(1)=π(2)=1`，每辆局部可见实车仅计一个未来需求，未来相位坐标为`s=x+φ(π(lane))`。同一π需要一致用于局部负荷、anchor/centers、matches及完整层判定；未来两资源各恰一辆且实际几何匹配才算应保护的完整层。这样原01层失去保护是按新资源图重新判断的结果，不是为增加换道而绕过保护。动作候选、相邻道、8m物理走廊和response_cost仍只用真实状态，π不能冒充实际占道或未来轨迹。未来图与真实phase、加入目标之间还需另行几何合同核验；这是有理论连贯性但比单行load映射更广的候选定义，不能仅以counts版本的结果否定整个方向。

后续1750/2000基线完整轨迹和候选对照在原runner封口后再追加独立新输出目录，既有数据不回写。

短筛180秒案例可以明确使用`audit_raw_midflow.py --window-start 30 --window-end 180`获得共同需求期诊断；默认600秒基线仍为[100,600)。每次输出保存实际窗口和完整性，独立从原region_steps账本重构同一窗口核对，不使用未完成窗口的旧均速指标冒称完整。
