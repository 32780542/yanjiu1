# E：用真实接收间隙直接变换，删除提前等待链

高需求轨迹显示，旧接收开隙会让继续车道跟随关闭车道停车；两车已相距不足8米时，接收车停车也无法把间距倒退扩大到8米。与此同时，关闭车道车被道路末端约束，双方等待使合流长时间停滞。远处helper选择也不保证被选车辆在自己的视野中选到自己。

本候选删除旧 `_make_room`、`_receiving`、`_receiving_distance` 及其协作分支，不增加新规则。继续道沿真实前车行驶，终止道车辆各自跟踪当前实际F/R间隙、调整到原中点并在真实_clear成立后横移。前200/后100米感知、相位交错、局部形成补位、准备区两道构型、必要合流优先、原CTH与安全执行保留。

它在控制行为上等于诊断NC，清理掉NC中不会运行的代码，便于后续在同一简单基线上检验自主单向疏解。NC的180秒小批只是筛查，不能直接代替正式验证。

合同检验终止道后车主动调整自己的gap、接收车不为虚构腾位压速、阻塞中道车不被绑定到不可执行helper角色，以及必要合流/硬安全保留。基线5项中预期失败见operation `20261103T032243958112Z_staggered-direct-gap-red_4a3eb540`。

构建命令：`python -B docs/experiments/2026-11-03-staggered-bottleneck/candidates/direct_gap/build.py`。在通过NC精确行为等价审查后，复用已跑NC案例；不为纯删除重跑相同物理实验。
