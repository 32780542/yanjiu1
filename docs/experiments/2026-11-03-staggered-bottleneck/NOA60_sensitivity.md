# 默认前车范围60m敏感性：NOA对NOA

正式基线仍为原NOA50，没有改写其规则、原结果或正式表。本研究把NOA60作为独立敏感性对象，两侧模式均为`noa`。
不是编队/相位消融，不把结果归因于形成规则，也没有读取final61性能。

原观测范围仍为前200m/后100m；变的是公共实际前车跟驰的默认搜索阈值50→60m，不是增加全局信息。
同一函数默认值也会影响`cf_speed`源码，但本NOA模式不执行组织/自由补位成本分支；实际变化来自默认front范围及其后续速度/普通驾驶反馈。
不能说所有后续动作被固定不变。L默认front仍50m，只在其组织分支出现真实单格witness时条件扩至60m；无条件NOA60不是L的完整机制。

## 原件与共同计划

新 `tools/report_noa_sensitivity.py` 复用原seal、协议核验、pair和等种子均值，不改原规则/报告工具。
每对强制相同需求hash、参数hash（含duration/max_time/执行器/SUMO）与所有非rule源hash，仅允许敏感性规则hash不同；两侧formation参与车辆秒均为0。

- 短180：参考池为原TM32/1250八例中20个NOA，目标16例。只配共同16对；原1750的4个额外参考不造pair。
- 长600：原31–35 NOA40作为参考池，NOA60只计划2250/2500×五种子×两道路共20。只配共同20对，额外1250/2000的20个参考不造pair。
- 两报告分别36/60个池病例全部协议、归档、safe/drained通过；16/20共同配对全部eligible。额外工况显式写入`reference_only_plan_keys`。

全字段、源/协议hash、原始差值及组均值见 `NOA60_sensitivity_short180/` 与 `NOA60_sensitivity_long600/`。
不对不同需求时长和种子组混算整体收益。短批不满原[100,600)区域窗口，相关正式指标保持null，不能补成0或另换时窗。
