# 高流量TM通行恶化：三例冻结源事件诊断

2026-11-03。条件：每上游道2500辆/h、seed1、180秒发车、500秒绝对上限、3→2；原冻结TM源`tmp/staggered_bottleneck/20261103_TM_load180_32/sources/TM`，仅启用原引擎`--diagnostic`。三策略均为同一规则SHA `65142b448412325357bab0bdcdc6fa6caaa75cddef2c6a498ab4d49454441317`，无生产修改。每例独立`run_logged --timeout 600`，Windows私有Job管理子进程；三例均退出0、安全排空、碰撞/瞬移0。原始轨迹在新目录`tmp/staggered_bottleneck/diagnostic2500_20261103/{transform,noa,formation}/`。

**事件证据指向transform接收开隙与必要合流之间的不可实现间距及低速传播：接收车常已离关闭道车辆不足8米，仍以其后方8米为目标停车；关闭道头车停在真实道路末端，无法前进补足间距。继续车道随之被主动拖慢，后来多个接收者轮流停车、腾位，头车长时间等不到实际可用空隙。** 不能泛化为“所有形成都堵塞”：本例普通formation的TT比NOA还短；也不能只把拥堵归因于安全执行器拒绝，它在三例均未拒绝横移。

## 4. 影响沿继续车道传播，远早于末端

180秒`v2_01068`在lane1、x713.699059、v1.224765，选择`open_gap`接收lane2的`v1_01275`（x719.570995、v1.985207、`ending_follower`）。两车仅差5.871936米，接收目标x711.570995在本车后方2.128064米。此时接收者共同安全上限3.797578，实际组织请求更低，为1.249170；继续车道没有前进到可行位置，而在追踪关闭道队列低速。300秒它仍在lane1、x851.895275、v1.846048，接收另一个`ending_follower`，同道前车也已低速。它144.0–360.1秒连续216.1秒低于5m/s。

## 6. 下一步最小因果试验及限制

1. 优先独立消融“所有关闭道候选都触发接收”与“在不足8米时继续追踪不可倒退目标”，保留现有真实安全走廊及原生发车；不以缩小安全距离消除循环。可检验只对当下可实现的实际合流空隙提供接收，或让已无法在本车后方成隙的接收者先按真实前车向前释放。候选必须明确处理关闭道头车与低速后继者的区别，避免把低速关闭道队列横向复制到继续车道。
2. 形成规则、transform提前二道相位、接收/腾位同时存在于当前策略差异中；formation优于NOA只证明本例不宜一概禁止形成，**尚不能把全部40.974秒差因果归给一个函数**。应分别做接收、腾位、相位/自由补位消融，配合同输入多种子验证。
3. 本诊断只有一个高需求种子和180秒脉冲，不能代替五流量/多种子/600秒验收，也不能证明最终容量。三例全部排空和安全均须保留；低流量已有优势、尾部负结果及燃油代价继续沿用原报告，不覆盖旧结论。
4. 只增加离线评价与原引擎开关，0/1参与/连续时长没有新增阈值。全局ID仅用于事件级解释。没有实现或采用候选，没有提交Git。
