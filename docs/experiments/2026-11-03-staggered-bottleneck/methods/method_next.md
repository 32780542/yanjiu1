# F：让本车使用实际交错空隙，单向分担未来负荷

2026-11-03。F在独立E（direct_gap）之上研究一个新假设：取消不一致的远处helper指派后，由每辆中道车依据自己的实际空隙与未来两道负荷，决定是否立即向左疏解；在准备区内保持单向迁移。F不叠加A投影、C筛选或D相位修正。

## 1. 旧helper为何可能没有车辆真正承担

冻结TM的 `_make_room` 从本车x先向前选90m内的终止道head，再从head向前90m内选anchor。options只位于 `anchor.x−30 .. anchor.x+15`。在足够长的密集队列中，anchor可以领先本车约180m，本车自然不在options中。别人选中的helper，在它自己的窗口里又向前推选出另一辆。

以下已直接调用冻结177f7a3函数复算，不是交通仿真。构造每道30m间隔：lane1在 `700+30k`，lane0/2在 `685+30k`，k从−5到30；每车只给其前200m/后100m观测。所有速度28.8m/s、无横向速度。

| 中道本车x | 它看到的head.x | 它选的helper.x | 它是否选中自己 |
| ---: | ---: | ---: | --- |
| 700 | 775 | 880 | 否 |
| 730 | 805 | 910 | 否 |
| 760 | 835 | 940 | 否 |
| 880 | 955 | 1060 | 否 |

这是局部选举缺少自洽的反例。它不能单独证明所有实际拥堵都由此产生，但能解释“多车推测存在helper，实际make_room执行却很少”。旧lane0 `_receiving` 还可依据自己推算的helper作接收控制，即使那辆H自己的控制器没有提交横移。只有目标速度确实降低时才产生额外制动；不能把所有open_gap原因帧都当成制动帧。

旧 `ending_follower` 在本车目标道不clear时提前返回，连本车真实F/R空隙的纵向接近都不再计算。这与虚拟接收前驱/预测helper形成没有物理承诺的等待关系。E已干净删除这些协作分支；F不在其上恢复一个更复杂的选举协议。

## 2. 3→2必须让左道承担多少

仅用于解释和全局评价：若三个输入道的流率为q0、q1、q2，中道向左转移r，则两个下游道负荷为

```text
Q0 = q0 + r
Q1 = q1 + q2 - r
Q0 = Q1 时，r = (q1 + q2 - q0)/2
```

三道等流量时，需要约一半终止道流量对应的中道车辆向左分担。让所有lane2只插入lane1、lane0只被动保持本流，不能消除下游不平衡。控制器不读取这些全局流率，也不按一半比例预编号。

本车固定窗口W=`[x−60,x+30]`内实测各道辆数为n0、n1、n2，定义本车未来负荷差

```text
P = n1 + n2 - n0
```

lane2→1的必要并入不改变 `n1+n2`；中道本车1→0则把P减少2。因此在单次横移、窗口车辆和其它动作均固定的反事实中，`P>=2`使平方不平衡下降：`(P−2)^2−P^2=4−4P<0`。这是局部动机，不是全网Lyapunov函数或稳定性证明。移动车窗、不同车速、并发横移可使窗口计数变化；P是空间负荷代理，不是精确流率估计。

原 `_fill` 在准备区按剩余两道的当前计数工作，尚未并入的n2不进入其均衡目标，可能把刚疏解到lane0的车又搬回lane1。F在准备区内停用这种自由补位，保留出区后的原形成规则。

## 3. 单一规则及最小入口

仅在 `preparing and mode == transform` 的存续道分支实行：

```text
先完成本车已提交/正在执行的横移（沿用E既有优先级）
若本车lane1：
    W = 本车实测窗口[-60,+30]
    P = count(lane1 or lane2 in W) - count(lane0 in W)
    若 P >= 2 且 clear(ego, observed, lane0)：
        立即提交本车1→0；沿用本车lane_target/joining及真实gap执行
    否则：沿用当帧既有following，不绑定新gap，不为疏解减速
若本车lane0：沿用当帧既有following
存续道本帧直接返回，不再执行自由fill
lane2：仍独立使用E的实际F/R目标与clear必要并入，不等待远处head
```

入口只在E `_decide` 的实际必要合流分支前增加10行，没有新辅助函数、参数或Memory字段。既有 `following` 在有同道前车时仍是真实前车CTH；无前车时保留E原有局部队首相位规则，不能把F称为删除相位。`clear`仍是8m当前/1s外推走廊，最终safe_speed仍读真实占用。

本车1→0须当下可行，不调用另一个车的隐藏计划；左道车不预先为其开隙。新横移方向在准备区均为2→1或1→0，lane索引严格下降，从车道迁移层面消除0↔1往返。此性质不证明纵向相互作用无环，也不覆盖进入准备区前已经提交的旧横移。

交错的作用是提供眼前可直接进入的真实几何缺口；它不是统一slot坐标。没有预设奇偶队号、共同层序、前驱通信或邻车状态位。track仅用于本车观测跟踪与安全排除自身，优先条件中没有真实ID。

## 4. 原文能支持什么

[Cai等作者稿](https://arxiv.org/pdf/2103.10287)§III-A/Fig.4讨论交错留空；§III-B的式(10)–(11)区分路径冲突，§III-C指出部分冲突不能只靠等待解决。其全组分配与目标交换不适用于这里。F仅借“利用当前空隙、改变导致等待的空间结构”的设计动机，局部P与单向规则均由本项目自行提出。

[MOBIL作者原稿](https://www.mtreiber.de/publications/MOBIL_TRB.pdf)§2.1式(2)以目标道后车的换道后减速度约束安全；§2.2把本车与受影响邻车的纵向响应纳入换道动机。这支持F必须核查新后车制动代价，不能把8m横移可行当作交通收益。F首试按约定不新增CF门槛，因此不是完整MOBIL移植。

Rupp2018仍只有[出版社摘要](https://www.sciencedirect.com/science/article/abs/pii/S2405896318307808)与[作者官方海报](https://tugraz.elsevierpure.com/ws/portalfiles/portal/11137142/SummerSchool.pdf)可直接核；正文403的限制继续保留。F没有使用其未核实滑模公式、拓扑条件或性能定理，也没有借“无通信”标题替自己补保证。

## 5. 必要条件及可证伪处

- 当前左道须有实际可行走廊，否则F保持跟随，不制造虚拟接收任务。缺口完全缺失时不能保证继续疏解。
- 8m安全走廊与30m巡航CTH平衡不同：插入15m+15m仍可能产生实际后车制动。F只消除前置虚拟等待，不消除空间守恒。
- 两道自由巡航平衡的理想上界是 `2*3600*v/(5.5+HEADWAY*v)`；在28.8m/s时为6912辆/h，在33.3m/s时约7087.59辆/h。这是由现有CTH自行计算的稳态参照，不是SUMO实测容量，也不把有限请求窗口的排空速度误写为不可能。
- 多车同时看到相似P可并发疏解，不能假设它们形成互斥调度；最终仍依赖实际安全执行。若lane0制动增加、全程时间或尾部排空恶化，必须否决，不能只报lane1负荷下降。

F与E必须同输入独立对照；全程/分段时间与安全排空之外，特别看lane0/1实际流出量、每次local_relief目标后车的减速度/低速时长及重复横移。E→F包含“自主单向疏解+准备区不逆向补位”这一个政策；不能仅凭改善把两项各自贡献拆开，需要后续独立消融才能区分。
