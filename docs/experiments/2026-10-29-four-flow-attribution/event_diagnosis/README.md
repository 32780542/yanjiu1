# P 严格横移完成事件诊断

本目录只读取 P100 与 C1_P20 已有 `result.json`，统计其 `lane_completion_events`；不运行 SUMO，不重算交通评价指标，不修改任何原证据、分析结果或正式包。

- P100 覆盖四流量、种子 6–10 的全部 NOA、formation、transform 例次；C1_P20 单独标识为 `C1_P_strict`，不跨源或跨标签混合。
- 成功次数使用实测严格横移完成事件。原引擎在目标车道索引正确、距中心小于 0.05 m 且横向速度小于 0.05 m/s 时记录完成。`lane_changes` 的索引中点、请求计数、`fill_layer` 等分支计数均不当作成功次数。
- 区间按事件完成位置分为 `x<640`、`640<=x<1000`、`x>=1000`，不是按发起位置分区。逐例核对数组长度等于 `lane_change_completions`，且三个分区之和等于总数。
- 横移分区 `x<640` 与既有时间区间 `100–600 m` 并非相同范围；此处不能估计“每次换道造成多少秒延误”，也不假定所有延误都发生在事件完成位置。
- 每车横移数以该例全部请求车辆数作分母。组表同时给出等种子平均的每车次数与总次数/总请求数，避免把两种平均混淆。
- `action_reasons` 是逐车逐步的命令分支计数；同一次执行可重复出现多个时间步，拒绝的请求也可被计数。结果事件没有逐次绑定的 rule reason，因此不能把它们与具体成功横移一一对应，也不能凭分支总数把延误全部归因 `_fill`、让位或某一规则。
- 既有 P_analysis 中的分段时间和完整多层参与值只原样摘录，并保存来源 SHA；没有用事件数新增交通评价标准。额外动作与上游延误共同出现，支持“组织过程伴随额外动作和成本”的描述，不能单凭相关性确定某条规则的全部因果贡献。
- 上游完整多层参与很少时，较多横移也不等于形成了更多有效编队。机制判断仍须结合原有分段、低速、燃油及严格消融结果。

`runs.csv` 为逐例完成事件计数，`groups.csv` 为来源/流量/道路/模式汇总；动作分支计数独立保存在 `action_reason_runs.csv`、`action_reason_groups.csv`。`P_existing_context.csv` 原样保存相关正式均值；`P_transform_vs_NOA_descriptive.csv` 只作描述性对照。

`source_input_result_index.json` 绑定每例源、input/result SHA。独立复核会按索引重新读取这些原结果，仅重数既有事件和复核汇总，不重跑仿真或重新评价交通性能：

```powershell
python -B verify_event_diagnosis.py
```
