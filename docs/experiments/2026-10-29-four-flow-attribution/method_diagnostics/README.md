# 方法诊断与阴性结果归档

本包只保存指定候选目录中已有的源码、冻结文件、总结、测试及证据索引，不重算交通指标，不重跑仿真。原始目录保持只读。C0/C1 正式包未改动。

- **E1/E2 系列**：保留双向反馈、增益与巡航约束等独立源码身份。指定包内没有专属实验总结的版本，明确记为证据缺口，不从目录名补造性能数值。
- **E3 系列**：平衡相位探索与早期自身执行反馈分别存档。已有质量总结中的未完成结果保留；自身 pending 请求被错误重绑属于执行生命周期缺陷，不能解释成流量拥堵。
- **E5/E6/E7**：执行修复、邻车速度及速度差反馈探索不能全部归入“追远车/错层/开隙”三项。六车能形成不代表连续流成功；E7 既有总结中 1500 流量变换行程 59.182841 s、同探针 NOA 42.791421 s，且上下游完整参与为零，拒绝结果保留。
- **E8**：真实前车只要可见就继续追赶，切断了部分旧分支错误，却造成整串提速。既有 1500 直路平均速度约 32.50 m/s，上游完整参与为零；全程快不能当瓶颈收益。
- **E9/E10**：跨道车身互选可能把中车对到对道头车，留下悬空首尾。E10 实测 34.7 s 虽为两道各三车，却只闭合成中间四车两层；原记录和反例保留。
- **E11**：改为真实局部队首互选，跟车只沿前车链。打乱六车形成与原六车变换通过，属于功能证据，不能直接推成交通提效。
- **J**：空间连续相位修正了静态坐标/权重反例，但短轮行程方向混合，下游稳定参与下降。相位场连续不等于完整控制连续。
- **K**：坐标速度补偿满足其期望速度层面的不变量，但两例瓶颈段时间仍劣于 H；不构成全系统零和或稳定证明。
- **N**：共同配对构型加真实后车压缩辅助后，短轮行程改善不一致。它同时改了几何和后车项，不能把全部损失都归因后车项。
- **P 校准版 `d72154c2`**：移除 N 的后车辅助，保留共同离散配对构型；短轮收益仍混合。后续发现“仍为 lane2 的车辆被提前按两道处理”的几何反例，原版结果不改名、不覆盖。
- **P 发布版 `8d112d79`**：仅在双方实测车道索引均小于 2、且双方位置均过边界时使用两道构型；否则保持三道。保留 H 的 50 m 前车链，无 N 后车辅助、无 J/K 空间场或雅可比补偿。两种六车证据与范围修正 R/G 原日志保留。P100 与 C1_P 统计由正式分析负责，本包不宣称交通成功。

`review.json` 给出 P 的局部信息、几何边界与声明限制。“实测 lane2”指 SUMO 车道索引；它不等于整个车身已经离开终止道。共同配对误差的静态反号，也不等于所有车辆实际动作互反、零和或全局稳定。

`method_diagnostics.tar.gz` 使用内容地址去重保存每版六份核心源码，并保留已有元数据、测试/小型 fixture。没有递归读取 results，没有复制 positions 或大 region CSV。原 case 路径、已有 SHA、协议与 R/G 操作标识在原始总结及索引中保留；缺失的原日志只保留索引，不补造内容。

`manifest.json` 记录每个 tar 成员的 SHA256、来源文件、各版本六源码映射和缺失项；`manifest.sha256` 绑定清单。包中的 E2/E3 子版本与 P 校准/发布版各有独立身份，不能跨版本混平均。

独立核验，无需 tmp：

```powershell
python -B verify_archive.py
```

核验只检查归档、源码映射、哈希与已保存材料，不运行控制器或重新计算评价指标。
