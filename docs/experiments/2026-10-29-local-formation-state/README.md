# 本车0/1编队状态与直接统计

本轮按用户确认的口径实现：车辆自己根据已有局部关系输出0或1，记录器收集全路输出并统计。控制仍是P的固定间距、局部队首和实际空隙规则。本轮没有实施固定时距，也没有改变速度、换道、入口或安全执行。

## 状态怎样产生

`Command.formation_state`为整数。组织模式中，当前走廊前方50米内有真实前车、同道后方50米内有跟车，或与相邻道队首互选时，输出1；否则输出0。NOA始终输出0。同道后车关系将链首纳入，已对齐且修正速度为零的头车仍可以为1。

允许仍在调距或横移，不增加完整层、间距误差、1秒确认或5秒保持等判定。关系按当前局部实车重算，不保留过期状态。字段只进入记录器；邻车观测中没有该字段，没有状态广播。

## 哪里可以看到

- 每个0.1秒的`positions.jsonl.gz`帧增加`formation_states`，例如`{"a":1,"b":0}`；原运动数组不变。
- 开启`--diagnostic`后，动作记录也带`formation_state`。
- `result.json`的`formation_state`对象保存参与率、平均/峰值同时参与人数、连续1段数及平均/最长已观测时长。
- 根目录`runrun.py`结束后直接打印参与率、参与人数峰值和平均连续1时长。
- 常用`experiments/native_comparison.py`对新轨迹直接重算0/1统计，不调用完整层检测。

参与率是状态1车辆秒除以全部车辆秒，平均人数是状态1车辆秒除以观测时长。前一帧积分到下一帧，末帧不外推。输出0或离场结束一个连续段；记录结束仍为1时使用已观测时长。没有车辆时间时参与率为空，有车辆但始终为0时为0；没有连续1段时保持时长为空。

同时参与人数是全路总数，可以包含多支车队。0/1没有队伍编号，因此本次不将总数标作单支编队大小。连续1时长表示持续参与，期间可以更换局部伙伴；纵向波动是否放大仍由跟驰动力学检验。

## 验证结果

206项核心测试、29项子测试、9项根GUI检查通过。900个随机局部状态与冻结P逐项比较了速度、目标、换道、原因、引用和私有记忆，全部一致。

另外，1500辆/(h·车道)、seed6、60秒请求，在三道直路与3→2道路共运行5对P/新增状态版本，每例80辆全部安全完成。全部物理轨迹逐帧相同，逐车trips文件逐字节相同。此表为状态输出回归的示例，不与原600秒、多种子的正式矩阵合并。

| 三道直路 | NOA | 0% | 0 | 0 | 无 |
| 三道直路 | 编队 | 95.397% | 32.168 | 60 | 30.074 |

完整数值及原目录见[summary.json](summary.json)。新状态表示已有局部关系，历史完整层参与率表示另一种几何条件；数据分别保留。新增状态前后交通结果一致。

回归过程曾出现一个旧三元组断言未同步的失败，已改为包含第四项状态，前三项驾驶断言保留。初始测试、一个测试用例ID修正、预期失败及最终通过日志均在证据包中。

## 精简证据

[evidence.tar.gz](evidence.tar.gz)约2.33MB，包含83个成员：当前源码、测试、原运行日志、10例原input/result/trips，以及一对3→2编队变换的完整新旧轨迹。其余8份大轨迹在本机原目录保留，大小和SHA256记录在summary中。旧P源码引用[已公开冻结包](../2026-10-29-four-flow-attribution/portable_P/source)。

核验公开包并独立重算所含状态轨迹：

```powershell
python -B docs/experiments/2026-10-29-local-formation-state/verify_evidence.py
```

核验只用Python标准库，不运行SUMO。它检查全部成员SHA、所含新旧物理帧与逐车账本，并独立累计0/1的车辆秒和连续段。五对完整轨迹的一致性检查原日志也在包中。

旧完整层模块保留供历史报告复算。当前全部规则与字段定义见[系统说明](../../原生SUMO编队变换系统说明.md)。
