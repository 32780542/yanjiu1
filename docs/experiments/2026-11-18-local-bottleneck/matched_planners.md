# 同一辆 NOA 车，换三种驾驶方法

本页采用修正后的普通车控制。原车型的协作调速和环岛子权重均为 0.5，项目已按运行时数值恢复。两个限速下的 30 个普通车案例已重新运行，NOA 和编队使用同批原始行程，三组重新逐车汇总。旧值保存在提交 `88fa24c`。[奖励、路线预见、邻车让行与时距的逐项核查](hdv_information.md)

## 三种方法怎样开车

**Cai 普通车控制。** 本地 MATLAB 工程把普通车的速度交给 SUMO 的 IDM。前方空旷时，车向道路允许的速度加速。接近较慢的前车时，IDM 根据实际净距、速度和接近速度调节加速度。横向使用 SUMO 的 LC2013。它会根据行驶路线判断本车道能否继续向前，也会为提高速度、给邻车让位或靠右行驶而换道。普通车入场后使用速度模式 31、换道模式 1621。代码保留 Cai 的换道速度收益权重 0.3 和协作权重 0.5，两者写入每辆车的换道模型。MATLAB 中的 `lcImpatience=0` 是子车道模型的参数，当前 LC2013 用前两项。这一组对应 Cai 工程里的普通车分支。论文中的集中式编队另有规划器。[MATLAB 普通车分支](matlab_audit.md) · [项目实现](../../../variants/phase5g_pure_formation/run_cai_hdv.py) · [SUMO 对换道模型参数的定义](https://sumo.dlr.de/docs/Definition_of_Vehicles,_Vehicle_Types,_and_Routes.html#lane-changing_models) · [SUMO 对模式 1621 的说明](https://sumo.dlr.de/docs/TraCI/Change_Vehicle_State.html#lane_change_mode_0xb6)

**纯 NOA。** 每辆车观察三个车道，范围是前方 200 米、后方 100 米。正常行驶时，50 米内没有占用本车道的前车便请求以 28.8 m/s 巡航。有前车时，根据前车速度和间距误差调速。同道目标为车头到车头的距离 `D(v) = 4 + 1.5 + 0.85v` 米。前车和本车都比巡航慢 2 m/s 以上时，若相邻道的前向空距多出 15 米以上，且横移安全，就可以超车。终止道车辆在距缩道点 200 米内看到车道结束后，寻找中道空隙。空间不足时它可减速对准中道前车的后方，并保留能在车道末端停下的余量。[跟驰、超车与必要合流](../../../variants/phase5g_pure_formation/noa/native_rules.py)

**分布式交错编队。** 车辆使用相同的局部视野和同道间距，在相邻车道寻找能与自己错开半个车距的邻车。本车用自己的观测判断双方是否彼此最合适，随后小幅调速。以 28.8 m/s 行驶时，同道车头间距为 29.98 米，相邻道错开 14.99 米。缩道时，终止道车辆可以根据自己看见的车道末端，或本车道前车已经开始的横移，发起并入。中道车辆会把有条件汇入的前车纳入跟驰判断。当另一条存续道实际有合适空位时，中道车可以向该道接续。每辆车自己检查当前空隙和未来一秒的相对运动，决定是否横移。整个过程使用本车观测和本车记忆。[交错配对、空位选择与换道](../../../variants/phase5g_pure_formation/noa/native_rules.py)

## 哪些条件相同

每一组配对实验共用同一份 SUMO 车型和来车文件。车辆长 4 米、宽 1.8 米，静止净距 1.5 米，车型 IDM 时距 0.2 秒，加速度上限 5 m/s²，常规和紧急减速度分别为 10、30 m/s²，最高速度 33.3 m/s。速度倍率为 1，倍率离散和 `sigma` 均为 0，排放车型为 `HBEFA3/PC_G_EU4`。IDM 的其余属性由同一版本的 SUMO 读取同一组默认值。0.2 秒是三组共同的底层 IDM 参数。0.85 秒是项目两种局部方法主动追踪的队形或跟驰目标。两者在代码中承担不同的作用。[共同车型与发车生成器](../../../variants/phase5g_pure_formation/experiments/native_sumo.py)

道路上游为三车道 1000 米，下游为两车道 200 米。终止道车辆须在上游并入。三种方法用 SUMO 1.27.1，以 0.1 秒为一步，换道用时设置为 1 秒。每道独立生成 600 秒来车，需求为 1500、1750、2000 辆/(小时·车道)。每档使用种子 311–315，相同种子逐辆匹配请求时刻、初始车道、位置和速度。发车请求速度均为 28.8 m/s，车辆由 SUMO 实际插入。各方法使用其自身的决策和安全检查。两种项目控制共用同一个局部执行器。

每辆车的行程等于 SUMO 记录的实际驶出时刻减实际入场时刻。从第一辆发车一直跟到所有车驶出，五次运行合并后按车辆数求平均。另统计从第 0 秒到第 600 秒之前驶出 1200 米出口的实车数，乘 6 换算成辆/小时，再对五次运行取平均。这个出口流率包含仿真起步时段，所反映的是给定需求下实际送出的车数。

## 空路上的单车

一辆车从终止道驶入，路上没有邻车，因而没有结队机会。现行路网限速 33.3 m/s 时，Cai 普通车控制用 36.4 秒走完，纯 NOA 和编队均用 41.7 秒。Cai 控制下，SUMO 在入口后 671.80 米记录了一次路线需要引起的跨道。两种局部控制均在约 815.04 米记录到车道编号改变。缩道点位于 1000 米。原生换道器使用路线接续信息，两种项目算法直接观察道路的距离为 200 米。

把全路限速改为 28.8 m/s，车型最高速度仍为 33.3 m/s。这次单车行程分别为 41.8、41.9、41.9 秒。两种限速能区分自由行驶速度带来的差距与多车工况中的差距。[单车记录](stage/matched_planners/single_vehicle.csv)

## 多车交通效率

90 次正式运行完成 79,014 个路内行程，全部车辆驶出，碰撞和瞬移记录均为零。每个限速下各有 15 组三方法配对。逐组核对，车型和来车 XML 的每个字节都相同，生成的路网在去除运行时间、目录等注释后也一致。SUMO 的逐车记录均确认车型为 `CAV_ICV`、速度倍率为 1。两种限速下的 30 组配对，每一组都是 Cai 普通车控制行程最短，交错编队其次，纯 NOA 最长。

Cai 普通车控制换上 NOA 车型后，2000 档在现行路网的均值由原车型的 161.00 秒降至 37.58 秒。统一限速后它仍比编队快 3.68 秒。此时单车空路行程只差 0.1 秒，剩余差距主要出现在多车行驶中。两种局部控制主动追踪 0.85 秒时距，Cai 控制直接用共有 IDM 的 0.2 秒参数跟驰，还能按路线更早选择存续车道。这次得到的是整套驾驶方法的净差，单车观测确认了路线预见确实发生。各机制分别贡献几秒，需要另做逐项对照。[历史普通车型数据](onroad.md)

## 复跑

在项目根目录打开 PowerShell。第一组使用现行路网，第二组使用共同的 28.8 m/s 路段限速。每次复跑给批次与报告选一个新目录。

```powershell
$study = 'docs/experiments/2026-11-18-local-bottleneck/tools'
python -B scripts/run_logged.py --label matched333 --timeout 5400 -- python -B "$study/run_onroad.py" tmp/repeat333 --road-limit 33.3 --matched-tau
python -B "$study/summarize_onroad.py" tmp/repeat333 tmp/report333
python -B scripts/run_logged.py --label matched288 --timeout 5400 -- python -B "$study/run_onroad.py" tmp/repeat288 --road-limit 28.8 --matched-tau
python -B "$study/summarize_onroad.py" tmp/repeat288 tmp/report288
```

`run_cai_hdv.py` 默认使用 0.85 秒的普通车 IDM 时距。上一轮的 0.65 秒配置可用 `--hdv-tau 0.65` 复现。[当前三组结果](headway085.md) 复现本页的 0.20 秒共同车型实验时，传入 `--matched-tau`。复现早期完整 HDV 车型时，传入 `--original-hdv`。单车对照沿用每种方法各自的运行入口，使用流量 2000、种子 311、需求时长 1 秒和截止时刻 90 秒。这段需求只产生一辆车。[批量运行](tools/run_onroad.py) · [逐车复算](tools/summarize_onroad.py)
