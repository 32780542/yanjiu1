# 控制代码怎样执行

## 入口

运行根目录的 `runrun.py`。顶部四项分别控制每车道的来车率、来车时长、随机种子和窗口推进速度。SUMO 在第一次计算时打开，镜头可以手动移动和缩放。需要纯 NOA 时，运行 variant 下的 `run_native_flow.py --mode noa --gui`。

## 先看这三个文件

| 文件 | 阅读顺序 |
|---|---|
| `runrun.py` | 从 `main` 看入口怎样调用 `run_case`。 |
| `variants/phase5g_pure_formation/experiments/native_sumo.py` | 先看 `arrival_tape`、`LocalTracks.observe`，再看 `run_case` 的逐帧循环。SUMO 执行真实发车和运动。研究记录保留每步位置、各车 0/1 状态及换道事件。 |
| `variants/phase5g_pure_formation/noa/native_rules.py` | 从 `decide` 读起。纯 NOA 的判断在 `_reactive`，编队形成在 `_following`，缩道接收和空位检查在 `_queue_front` 与 `_vacancy`。 |

## 一帧里的六条规则

1. 当地视野提供前 200 米、后 100 米各车道内的实际车辆。本车距终止点不超过 200 米时，仿真适配层才把道路终点交给本车控制器。默认用直接道路观察。
2. 同车道跟随实际前车。正常编队关系在 50 米内建立，有已建关系时可以继续跟随 200 米内当前实际前车。相邻车道互选邻车后，通过纵向调速形成半间距错位。目标同道车头距 (D(v)=5.5+0.85v) 米。
3. 终止道车辆看到缩道，或看到当前真实前车向接收道横移，或已有自身未完成的退道计划时，准备向车道 1 并入。只有当前和短时预测走廊通过安全检查，才下发本车动作。
4. **这次加入的规则**是等待安全空隙时先保持当前车道的纵向跟驰。终止道车辆只有在安全检查允许发起并入请求，或本车动作已在执行时，才用目标道实车作纵向接续参考。目标道和候选锚车仍可在本车记忆中保留。没有本车道前车时以巡航请求为起点，并受实际安全上限约束。
5. 中间车道只有找到前后安全、符合交错接续关系的真实空位才向车道 0 补位。当终止道已在视野内，或前方实际终止道车辆正在横移时，车道 1 的接收车辆可以把这辆车作为纵向参考。候选必须在本车前方，且当前和短时预测净空允许接入。每次动作只跨相邻一条车道。
6. 每辆车分别通过纵向制动上限、车道走廊检查和 SUMO 安全执行。纯 NOA 保留安全主动超车和必要合流。若需要并入但走廊被挡，NOA 可以按目标道前车适当减速，同时服从本车道跟驰请求。它与编队共用路网、来车、车辆参数和基本安全限制。

控制器的私有记忆只有本车目标道和实车追踪引用。不同车的追踪编号各自独立，邻车私有计划和评价数据不传入控制。评估层可以汇总所有车辆和轨迹。每车输出 1 表示已有编队关系，实际交错由物理位置和车道状态另行评价。

历史阶段的 `run.py` 和 `demo/` 供历史报告复现，日常运行从 `runrun.py` 开始。读取旧封存结果时如果当前运行器的 SHA 已变，可用 `tools/restore_analysis.py` 从旧提交取回原来的 13 份分析文件。旧证据校验使用其本来的方法和哈希。

## 复算旧证据

从根目录恢复核查源到一个新目录。该工具只恢复 13 个小文件。

```powershell
python -B docs/experiments/2026-11-18-local-bottleneck/tools/restore_analysis.py tmp/nov18_previous_evidence_sources
```

对旧案例，取输出目录下对应版本的 `docs/experiments/2026-11-03-staggered-bottleneck/tools/seal_case.py`，执行 `verify <案例 evidence 目录>`。新的原生运行器已改变输入边界字段和源代码哈希。旧证据的哈希继续和它本来的方法文件比较，不用新运行器重签旧证据。

本轮归档记录原运行的源文件、输入、逐车结果和紧凑轨迹证据。完整位置和事件留在原批次目录。报告中的五种子配对来自明确的输入与验收记录，代表性热图的网格也单独保存。
