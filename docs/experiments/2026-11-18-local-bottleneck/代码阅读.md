# 控制代码怎样执行

## 入口

运行根目录的 `runrun.py`。顶部四项分别控制每车道的来车率、来车时长、随机种子和窗口推进速度。SUMO 在第一次计算时打开，镜头可以手动移动和缩放。要看报告中 2000 档、种子 311 的同一批车，可在项目根目录分别运行以下两条命令。

```powershell
python -B variants/phase5g_pure_formation/run_native_flow.py --gui --flow 2000 --seed 311 --duration 600 --max-time 1200 --mode noa
python -B variants/phase5g_pure_formation/run_native_flow.py --gui --flow 2000 --seed 311 --duration 600 --max-time 1200 --mode transform
```

## 先看这三个文件

| 文件 | 阅读顺序 |
|---|---|

## 交错间距怎样随车速变化

设车速为 $v$（m/s）。同道目标车头距为 $D(v)=4+1.5+0.85v$ 米。其中 4 米是车长，1.5 米是停车净距，0.85 秒是控制器的目标时距。选取这个数的依据是巡航时的队形。以 28.8 m/s 行驶、同道车头距取 30 米，反算时距为 $(30-4-1.5)/28.8≈0.851$ 秒，取到小数点后两位就是 0.85 秒。相邻车道错开半个车头距，巡航时为 14.99 米，减到 10 m/s 时为 7 米。两车有速度差时，横向配对以它们的平均速度计算目标错位。准备接纳一辆车时，两个半间距各须容得下 8 米的换道间隔，因而接入间距至少为 16 米。

## 一帧里的六条规则

1. 当地视野提供前 200 米、后 100 米各车道内的实际车辆。上游车辆在终止点前 200 米内才收到端点坐标。驶过缩道点以后，本车看到脚下已有两条车道，控制器以这个本地车道数接续。
2. 同车道跟随实际前车。正常编队关系在 50 米内建立，有已建关系时可以继续跟随 200 米内当前实际前车。相邻车道互选邻车后，通过纵向调速形成半间距错位。目标同道车头距 (D(v)=5.5+0.85v) 米。
3. 终止道车辆看到缩道，或看到当前真实前车向接收道横移，或已有自身未完成的退道计划时，准备向车道 1 并入。只有当前和短时预测走廊通过安全检查，才下发本车动作。
4. **这次加入的规则**是等待安全空隙时先保持当前车道的纵向跟驰。终止道车辆只有在安全检查允许发起并入请求，或本车动作已在执行时，才用目标道实车作纵向接续参考。目标道和候选锚车仍可在本车记忆中保留。没有本车道前车时以巡航请求为起点，并受实际安全上限约束。
5. 中间车道只有找到前后安全、符合交错接续关系的真实空位才向车道 0 补位。当终止道已在视野内，或前方实际终止道车辆正在横移时，车道 1 的接收车辆可以把这辆车作为纵向参考。候选必须在本车前方，且当前和短时预测净空允许接入。每次动作只跨相邻一条车道。
6. 每辆车分别通过纵向制动上限、车道走廊检查和 SUMO 安全执行。纯 NOA 保留安全主动超车和必要合流。若需要并入但走廊被挡，NOA 可以按目标道前车适当减速，同时服从本车道跟驰请求。它与编队共用路网、来车、车辆参数和基本安全限制。

控制器的私有记忆只有本车目标道和实车追踪引用。不同车的追踪编号各自独立，邻车私有计划和评价数据不传入控制。评估层可以汇总所有车辆和轨迹。每车输出 1 表示已有编队关系，实际交错由物理位置和车道状态另行评价。

## 一个三变二的实例

从车道 2 进入车道 1 的车先看自己的前车和车道 1 的实车。若目标道旁边正好有车，它先留在本车道。编队模式下，它保持当前跟驰，等目标走廊可用才开始横移，并接着跟目标道的前车。此时后方车辆可能尚看不见道路尽头，但能从自己的观测中看到真正的前车正在向车道 1 移动，于是也开始检查自己的间隙。两辆车可以在相近时刻变道，也可以因各自的空隙不同而一走一等。

从车道 1 看，则是另一个决定。当前方的车道 2 车辆已有机会并入，车道 1 的车可以把它视作即将接在自己前面的车辆，先调整自己的纵向位置。如果受阻，同时在车道 0 找到合适的实车空位，它也可以向车道 0 接续。三辆车分别作判断，依据都是眼前实车的位置、速度和横移。纯 NOA 也能主动超车、并入和调速，队形接续和依据前车横移提前退道属于编队变换模式。

## 规则文件的函数索引

| 要读懂的决定 | 对应函数 | 代码实际在做什么 |
|---|---|---|
| 本车能看到什么 | `LocalTracks.observe`（运行器） | 从实车位置中取前 200 米、后 100 米内各车道的车辆，为本车分配本地追踪号。运行器另传本车所在路段的车道数，并裁剪前方终止点的可见范围。 |
| 应留多远 | `desired_spacing`、`_entry_spacing` | 分别算正常车头距与可容纳并入车的接入间距。 |
| 交错目标在哪里 | `_phase`、`_physical_phase`、`_pair_error` | 按车道获取目标错位，换道途中按实际横向位置插值，再计算一对车的纵向位置误差。 |
| 谁是前车，应以多快的速度跟 | `_actual_front`、`_front_following`、`_request` | 找实际占用本车道或目标道的前车，把间距误差和前车速度合成下一步速度请求。 |
| 怎样形成交错 | `_following` | 在本车观测内匹配两侧相邻车道的实车，选择错位误差小、反向匹配也选回本车的邻车。纵向修正与真实前车跟驰相冲突时优先跟驰。 |
| 普通 NOA 怎样开 | `_reactive` | 跟驰、受阻超车、在可见缩道前必要并入。并入受阻时，只有目标道前车给出的速度更低，才按它调速。纯 NOA 的编队状态始终为 0。 |
| 怎样接收将要并入的车 | `_queue_front` | 检查前方实车能否进入本车道，从已有前车和可接收车辆中选纵向最近者。可见的真实横移也是判断依据。 |
| 中道车能否向另一存续道腾位 | `_vacancy` | 用目标道实车前车定位空位，检查空位前后、短时相对运动及与本车道交错位置的关系。已有计划优先复核同一辆前车。 |
| 什么时候能发动作 | `_occupies`、`_clear` | 用车身横向范围判断车辆占哪些道，再用当前和一秒后的纵向间隔检查目标走廊。 |
| 本帧采用哪个动作 | `_decide` | 接续自己的在途动作，处理终止道必要并入，再考虑中道腾位，返回本车的速度、车道请求、参考车、0/1 状态和下一帧记忆。 |
| 最后怎样限速、执行 | `safe_speed`、`decide`、`run_case`（运行器） | 按实际前车制动距离以及末道剩余距离限速。运行器逐车请求 SUMO 执行，跟踪横移直到车辆在目标道中心稳定下来。 |

评价时，某一时刻有 60 辆车报告 1，含义是当时有 60 辆车具有本地关系。这 60 辆可能分属多个车群。固定 45 车试验另用实际位置验证全体能否在缩道后重新形成两道交错。两项观测分别回答有多少车在参与、队形是否完整。

历史阶段的 `run.py` 和 `demo/` 供历史报告复现，日常运行从 `runrun.py` 开始。读取旧封存结果时如果当前运行器的 SHA 已变，可用 `tools/restore_analysis.py` 从旧提交取回原来的 13 份分析文件。旧证据校验使用其本来的方法和哈希。

python -B docs/experiments/2026-11-18-local-bottleneck/tools/restore_analysis.py tmp/nov18_previous_evidence_sources

python -B docs/experiments/2026-11-18-local-bottleneck/tools/restore_analysis.py tmp/nov18_verifier --revision f87f652
