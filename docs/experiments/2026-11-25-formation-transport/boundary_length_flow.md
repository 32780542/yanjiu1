# 连续流中，同一组 12 车需要多少下游距离

在 1750 辆/(小时·车道) 的连续来车中，分别把三变四、四变三的实际下游由 200 m 延至 1000 m。两个种子、两种道路各有一组 12 车在预视线前排齐。**四个原组在长路上都重齐并连续保持 22.5–29.8 s。** 三变四的两组首次重齐时，队首已越过原来的下游终点。四变三的两组在首 200 m 内就已重齐，延长下游后才观测到连续 3 s。

## 同一组车在不同下游区间的轨迹

上游长 1000 m，预视线在 $x=800$ m，车道数在 $x=1000$ m 处改变。以队首车辆首次穿过预视线的上一帧锁定 ID。仅计 1200 s 需求窗内的上游组，排空阶段无新增组。采用持续流主研究的整层、闭包、速度和原点判据。种子 9301、9302 在此前相邻版本中均出现过上游组，本对照先选这两组发车流，再运行长度实验。八场均完整排空，碰撞与传送均为零。

表内报告合格队形最长连续时长，单位为秒。“无”表示在该区间没有完整的一帧。每个观测区间都要求全组车身参考点同时落在其中。短路与长路首 200 m 的结果分别从两场 SUMO 轨迹读取。

## 入场与上游反馈

四对 SHA-256 相符的请求发车表均逐车检查了实际首帧。两段路长下，全部 7,997 辆配对车的实际入场时刻、纵横向位置、速度与加速度完全相同。需求窗内两场每 0.1 s 比较 $x<800$ m 的全部在场车辆，另核对每辆车在全程首次越过预视线的采样时刻。

## 复算

冻结版本为 `moment`。八场运行的 `noa/native_rules.py`、`noa/staggered.py` 与 `experiments/native_sumo.py` 的 SHA-256 前十二位分别为 `008fbbd6a9de`、`ddc6207d453f`、`78f779f2b024`。在独立进程中仅设定物理下游长度，运行后从实际生成的路网 XML 核对两段长度及车道数。默认复算从 Git 提交 `7bdeaca` 与已有镜像矩输入包恢复 12 个源文件，逐个校验 SHA-256。[冻结源码清单与镜像矩文件](moment_development_inputs.zip)

```powershell
$study = 'docs/experiments/2026-11-25-formation-transport'
python scripts/run_logged.py --label road-length-repeat --timeout 3600 -- python "$study/boundary_length.py" --out tmp/road-length-repeat
python scripts/run_logged.py --label road-length-repeat-check --timeout 1200 -- python "$study/boundary_length_audit.py" --batch tmp/road-length-repeat --out tmp/road-length-repeat-check
```
