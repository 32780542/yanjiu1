# R5 补齐单元：独立风险与测试设计（计划前审查）

日期：2026-09-13。状态：只读分析当前实现，尚未验收新的 R5 实现。作者负责 `docs/phase5_r5_completion_plan.md` 和独立版本实现；本文提出待对接的测试判据，不替代其实施计划。已冻结的 A/B 开发比较、heldout、v1 选择/汇总及结果不变；R5 新单元不是 B3，也不能补写为旧实验已经具备的机制。

## 当前代码提供的事实

- 规格 §9.5 要求以可见几何/公开道路规则让行，近同时无法判定时保守减速并本地随机退避；不允许内部状态、隐藏换道计划或配合成功假设。当前 `noa/controller.py` 只有候选、固定准备时间和执行后冷却；`NoaMemory` 没有竞争随机状态。
- `decide` 只读取 `ControlInput` 的自车状态、当前有限观测和自身记忆。`NeighborDetection` 有物理量和局部传感器标签，没有旁车候选、动机、prepare 计时、计划、种子或执行器内部量。
- 候选来自本车重建的可见相邻车道中心。PREPARE 期间仍发出当前车道保持命令；满足准备时长且到达 `behavior_dt_s` 的行为事件后才创建本车 `QuadraticLaneChange`。因此旁车没有开始可见横移时，无法由其内部 prepare 状态判断先后。
- `NoaClock.tick` 先冻结全体观察，再独立决定、积分、统一提交。这个实现顺序不是通信通道；先遍历的车不能把本轮决定暴露给后遍历的车。
- `verify_candidate` 使用邻车纵向硬界、当前惯性横向速度及登记的额外横向加速度界。该界目前为 **0**，必须保持。它不包络下一时刻突然开始的未知横向动作；检查也以本次自车纵向请求保持为条件。
- 已执行计划若预测失效，目前保持本车原参考并制动，不是可证明安全的中止/回撤规划。R5 不得将已执行参考清除后瞬间改为另一车道中心。

## 设计必须明确的边界

1. **只识别潜在竞争。** 当前可见物理几何可以表明一辆车已占用本车目标走廊、正在向其横移，或位于也可能进入该走廊的位置；它不能证明旁车确实选了同一空隙。竞争判据应明确其保守误报和漏报范围。不能以 `vy=0` 推断不竞争，也不能通过 fixture 的旁车计划补上这个信息。
2. **局部让行不是授权。** 可见已进入者优先、明显更靠前者优先只能从允许的相对位置、身体占用和运动推导；平局或观察歧义不能通过 ID、车辆类型、全局车道编号、奇偶、列表顺序或共同槽位解决。各车视野可能不同，局部判断不必一致；不存在共享“赢得空隙”标志。
3. **随机性只存在于本车。** 冻结 PRNG 算法/版本与取样区间，保存本车初始随机状态、当前状态/计数、触发事件、抽得的等待和绝对到期时刻。纯函数重复计算相同输入必须返回相同决定，重放不读取墙钟、进程熵或模块共享 RNG。离线 metadata 可以用 actor key 路由本车已封存的私有初态；在线不能读取真实 ID 算延迟，更不能按想要的先行车辆挑种子。不同私有流的统计独立性是初始化设计及有限实验范围，不能从“整数种子不同”直接推成公平性证明。
4. **同一退避事件有固定期限。** 需要规定事件创建、持续、候选失效、短暂丢帧、动机消失和退出的生命周期。每个 tick 用 `now+delay` 重置、每次重新 PREPARE 再计满同一等待，或以不断移动的绝对物理签名误判为新事件，都可能导致无限延后。到期只是重新尝试候选的资格，当前风险仍可否决；必须区分“已到期但守卫阻塞”与“计时器被自身刷新”。
5. **退避、准备与行为采样不能互相隐藏。** 需要预先说明等待和 prepare 是串行还是可重叠，实际开始只由原行为事件调度。不同连续等待经行为事件量化后仍可能同 tick 到期。一车先到期，另一车在其出现可见横移前也可能开始。重复抽取也可能再次相同；随机退避不保证互斥、有限时间成功、公平或无死锁。
6. **输出仍服从原安全和动力学。** 让行减速应明确如何与基础纵向请求组合，保留前车/车道终止/紧急优先，编队增量不能抵消让行。较小纵向请求不对后车或侧车安全单调有利；若修改即将执行机动的实际请求，原先针对另一请求的候选预测不能直接复用。不得通过位置/速度/执行器赋值实现瞬时让行，不改变任何硬界、舒适阈值、视域、扫掠容差或邻车额外横向界。

## 必要测试清单

| 编号 | 输入或反例 | 必须核验的结果 |
|---|---|---|
| I1 | 本车输入、私有状态完全相同；旁车隐藏计划分别为保持、已准备、即将并入 | 在出现物理可见差异之前，本车动作、记忆、抽样计数及诊断完全相同；测试 fixture 的全局预期不进入 policy。 |
| I2 | 置换局部 track 标签、输入邻车顺序、仿真 actor key、执行遍历顺序 | 固定同一物理车的私有初态后逐车结果不变；无先遍历者“通知”后遍历者。 |
| I3 | 自车、邻车和可见道路共同平移；范围外增加车辆或改其计划 | 局部规则/退避触发和相对等待不变；只有真实传感器可见变化才能改变决定。 |
| I4 | 对同一输入重复调用两次；两车交错调用；单车单独重放 | 每车序列一致；旁车调用次数不消耗本车随机流；模块无跨车可变状态。 |
| R1 | 退避首次触发、持续多个 tick，到期前后及多个行为事件 | 同事件仅按规定抽样，期限固定；到期当 tick、下一个合法行为事件的行为可解释，不因再次 prepare 自动延后。 |
| R2 | 明确不同私有种子/延迟，以及故意相同状态/相同延迟 | 不预设不同种子必有不同期限；相同状态可保持对称。同刻尝试/未完成必须保留，不能用测试夹具指定赢家。 |
| R3 | 连续延迟不同但落在同一个行为 tick；先到期者尚处 PREPARE 或尚无可见横移 | 不读取不可见阶段；不把先到期当成已占用；碰撞/双方拒绝/再退避均按真实结果报告，不能断言必互斥。 |
| R4 | 在等待中、刚到期、准备中、已执行时分别 JSON 往返并继续 | 恢复随机状态、期限、事件、prepare 和既有计划，未来逐 tick 完全一致；旧 R5 关闭路径仍与冻结基线兼容。 |
| R5 | 随机状态越界/计数非法、未来的起点、非有限期限、状态缺字段或互相矛盾 | 依明确 schema 拒绝，或只对有登记迁移规则的旧 schema 初始化；不能悄悄重播种或重启等待。 |
| L1 | 目标走廊已有可见车身、正在横移者、明显前车，以及几何近平局 | 分别覆盖可见让行与模糊竞争分支；边界两侧和完全相等情况不依赖标签。 |
| L2 | 只出现可能竞争位置但旁车保持车道；旁车朝相反方向离开 | 记录保守误报/释放条件，不宣称识别到了真实意图；不永久保留已不可见的竞争体。 |
| L3 | 竞争者离开视野、短暂空帧、重现、出现两个无法唯一关联的车 | 按有限记忆规定失效/退避，不在视域外外推真实计划；不利用持久 track_id 续接。 |
| S1 | 退避时出现紧急前车制动、真实车道终止、目标通道阻塞 | 原紧急/停车约束优先，不能为完成随机等待而巡航，也不能为到期启动而绕过守卫。 |
| S2 | 新候选通过后 R5 修改纵向请求；后车快速接近；编队开启/关闭 | 核验实际最终动作对应原候选检查条件；让行不是瞬时速度下降，编队不能加回已抑制的请求。 |
| S3 | 已有执行计划中出现竞争/新阻塞 | 本车参考连续、不被退避逻辑清掉或突然反向；保留原 active-plan 风险分支和失败边界。 |
| P1 | 两外侧车道、相近纵向位置、可能同时进入中间可见走廊 | 用原物理积分及独立真值审计记录每 tick prepare/退避/执行、首次可见横移、原预测结果、碰撞/越界/实际舒适性；不将全局真值送入决定。 |
| P2 | 已先行可见进入者；近同时双方；相同随机流；永不配合的固定脚本车 | 覆盖可解释成功与无改善/拒绝/失败，不只展示分离良好的随机种子。随机种子清单在结果之前冻结，不为获得成功补种子。 |
| E1 | 中断于决定前、抽样后未提交、物理积分中、同步失败 | 保存原失败边界与已产生输出；从输入中的自身 RNG 状态重算一致，失败不得额外推进共享随机或伪装为已提交。 |

单元 tests 可以直接构造局部不可见意图的等价输入；涉及真实几何、执行器、舒适性及碰撞结论时必须另有原积分/外层审计证据，不能用 mock 的 `safe=true` 作为物理通过证据。测试不以“任意竞争必形成/必并入/必避碰”为断言；确定性断言针对信息约束、状态生命周期、记录重放与守卫调用，物理成功率/失败原因是如实保留的实验输出。
