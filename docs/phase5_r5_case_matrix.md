# R5补全版本的固定机制案例

本矩阵在任何新版车辆实跑之前写定，与旧A/B开发选择及六保留种子实验分开。控制器不读取本表、车辆命名、旁车私有状态或外生脚本。下表所有x/y单位为m、速度为m/s，三车道中心为1.65、4.95、8.25；各车初始heading/加速度/转角均0。受控车共同目标仍5，原最小换道速度仍5，原模型/守卫/舒适限制不变。物理初态的确定性函数位于新副本`experiments/phase5_r5_cases.py`。

| 案例 | 固定时长 | 受控初态 | 外生车辆及自身脚本 | 要观察的事实 |
|---|---:|---|---|---|
| r5_single_clear | 20s | ego=(250,1.65,8) | lead=(310,1.65,2)，目标2 | 无近邻竞争时不抽随机，R5开关配对动作一致性 |
| r5_competing | 30s | left/right=(250,1.65/8.25,8) | 各慢前车在同车道x310，目标2 | 近同时潜在同中道竞争、私有抽样、到期与实际启动分离 |
| r5_speed_floor | 30s | left/right=(250,1.65/8.25,5) | 各慢前车在同车道x285，目标2 | 退避后速度低于原门槛；ELIGIBLE不等于能再启动 |
| r5_entered_priority | 20s | ego=(250,1.65,8) | lead=(310,1.65,2)；peer=(250,6.7,8)，自身目标8，0–5s既有Bezier参考6.7→4.95 | 可见已部分进入车身优先；不读取peer参考 |
| r5_front_priority | 20s | left=(250,1.65,8)，right=(254,8.25,8) | 各慢前车位于本车前60，目标2 | 4m可见前方优势与原2m优先边界 |
| r5_reentry | 40s | ego=(250,1.65,8) | lead=(310,1.65,2)；peer=(250,8.25,8)，自身速度目标(0,8),(3,14),(12,2),(25,8) | 尝试一次竞争退出/再入；若未产生第二episode或新抽样如实保留 |
| r5_same_private_state | 20s | 同competing | 同competing | 两车私有初态均1，不强制打破对称 |
| r5_quantized_private_states | 20s | 同competing | 同competing | 两车私有初态1、2，不同延迟落入初始同一0.5s行为区间；不保证随后同时启动 |

低速例慢前车距离35是运行前数值定义：以当前相对速度3、原10s超车展望及期望间距计算，可在初时形成原NOA候选；高速例距离60、相对速度6也在原动机范围。两者均不改变规则参数。是否真正通过后续预测、prepare和启动，以实跑为准。

普通六例共9个受控初始状态，每个调用一次系统`secrets.randbits(64)`，允许相同值，无唯一性筛选/重抽/按ID、车道或赢家派种。最后两例明确是对抗固定私有状态，不称独立熵样本。完整`FormationMemory`及来源字典在第一次tick之前封存，case中被控actor键只用于仿真路由；在线只注入该车自己的记忆。相同case开关两侧使用相同初态和私有记忆。

每例均运行R5 off/on（编队层保持开启），首例另做控制/感知周期同时减半，共17个登记变体；第一例按现有记录请求做0.005s积分检查。原0.01s实际积分、SUMO读回、道路/扫掠/约束、动作/记忆/抽样重放按原证据规则保留。`requirements`仍仅原驾驶条件，机制条件单独放入`r5_requirements`，不把未触发机制涂成驾驶碰撞，也不以记录通过冒充科学成功。

冻结JSON固定schema、生成器原字节hash、模型参数hash、完整物理case hash及含全部记忆/来源的完整case hash；加载器独立重建固定物理矩阵并核对，runner还须绑定输入原字节。已有目标文件拒绝覆盖，检查文件存在后才允许抽熵。最终整合新副本来源确定后才生成正式初态文件；开发单元测试的临时JSON没有车辆运行，不作为实验结果。

本矩阵只检验局部机制及其边界，既不进入旧B优选，也不证明全队恢复、无碰撞、互斥、公平性或任意初态收敛。固定脚本不能在运行中依据受控释放/选手行为调整；发生碰撞、拒绝、未完成、无再入或无改善均保存原始前缀。
