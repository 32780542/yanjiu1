# 阶段4模型、局部决策与证据语义

2026-09-11补齐后状态：固定小案例门槛通过，见[当前验收](D:/yanjiu1/keyan1/docs/phase4_completion_acceptance.md)。停车、并道动作一致性、横向反馈与行为/采样节拍的当前公式以[补齐方法说明](D:/yanjiu1/keyan1/docs/phase4_completion_methods.md)为准；原控制器初版说明保留历史范围。

新增参考只在既有0.5 s行为节拍启动；观测、安全检查和连续控制仍按0.1/0.05 s进行。反馈中的半周期外推只用当前允许观测，候选用最终实际请求验证。低速停止通过提前释放制动和有限弱尾积分达到零速；数值jerk门槛通过不保证连续时间jerk有界。

当前完整套件在运行结束时封存源码、输入与证据。补充采样包另于收尾时追加封存，逐案例输入与代码快照由其原记录提供，完整网络/参数登记快照共享同冻结版本普通运行；其事后来源与保护起点见[收尾审查](D:/yanjiu1/keyan1/docs/phase4_closure_review.md)。下文通用记录要求不能理解成补充入口当时已经自动完成整包封存。

主运动模型继续为 `models/kinematic.py` 与两段二次贝塞尔参考。阶段4新增NOA行为与安全筛选，没有引入质量、惯量、轮胎力、非理想感知或通信。车身4×1.8 m、轴距2.7 m、0.01 s运动积分、0.1 s控制/感知/SUMO同步及既有硬边界沿用。

## 控制与信息入口

`noa.controller.decide(ControlInput, parameters)` 是局部纯函数，返回动作、本车新记忆及诊断。`NoaMemory`继承既有LocalMemory，新增本车贝塞尔参考、目标车道中心、准备/完成时刻及计数；不会改写阶段3数据结构。历史观测沿用过去1 s窗口，正在执行的自车参考单独保留。参考是有限名义时长的本车计划，未完成跟踪时可能持续保持其终点；不能把此机制解释为保证有限时间完成。

道路由当前已裁剪的边界与标线转换至自车定位所用坐标，推导局部车道中心和物理收窄。感知区域被裁剪的末端不能当作物理终止车道。仅支持已验证的直路。绝对坐标用于自车位姿与几何转换，决策不写死1000 m、640 m等全局阈值，也不按邻车类型或编号决定优先级。

巡航、跟驰、换道准备/执行、并道和紧急状态由当前观测、本车状态及本车记忆决定。纵向跟驰采用速度、间隔及相对速度反馈，同时考虑带执行器响应和jerk的制动距离筛选。局部可见车道终点作为静止停车目标处理，低速停止保持仍由有限制动命令和运动积分产生，不直接把速度设零。

## 候选安全检查的范围

候选使用当前加速度请求和实际简化运动模型预测，横向跟踪两段二次贝塞尔。预测到名义换道结束后再留0.5 s收敛时间，每个积分区间检查带几何裕度的车身扫掠与当前已观测道路。

邻车纵向占用覆盖既有−10至5 m/s²硬边界并限制速度0–33.3 m/s；横向采用已测得的惯性速度，新增横向加速度范围首版登记为0。该假设不是传感器噪声，也不是他车保证让行；无法保证抵抗未来任意横向动作。所有可见邻车进入占用检查，不读取未来真实命令。目标转向限幅、候选通过和少量案例均不构成全局安全证明。

执行中候选失效时，当前实现保持原横向参考并制动，避免切换参考导致位置跳变。制动后实际运动与原候选可能不同，可能停车在车道之间或遇到无法避让的风险；独立检测必须报告这种失败，不能通过全局调度修复。普通换道、终止车道堵塞和强制急刹分别评估，不把触发EMERGENCY本身当作驾驶成功。

## 统一时钟与脚本干扰车

`NoaClock`先冻结同一时刻的全部物理状态，各自IdealSensor生成观测，然后独立决策、独立积分，最后FleetBridge一次性提交所有终态并推进SUMO一次。新记忆仅写回所属车辆。中途异常终止该实例，逐项保存已取得的输入、决策和子步，不重新排序车辆来解锁。

实验中的脚本车仅由自身状态和预先冻结的速度/加速度/贝塞尔日程产生动作；脚本函数不接收其他车辆状态或NOA决策。脚本用于提供可复现干扰，不代表完整HDV模型。角色和完整初态保存在实验元数据，NOA输入中没有角色标签。另设两辆车均使用相同NOA策略的独立多车案例，编队始终关闭。

## 验收与重放

每个案例分别保存 `recording_passed`、`driving_passed`、舒适性和总门槛。总门槛要求安全/任务完成、跟踪、舒适性和信息隔离通过。阶段整体还要求真实SUMO完整套件、同命令积分细化、采样细化、非空洞动作变化及篡改拒绝证据。压力案例的驾驶失败单列，不伪装为正常成功。

真值独立审计全车身扫掠、道路边界和模型包络；直接从运动状态计算换道完成、实际加速度、jerk和转向率，另报执行器jerk。换道轨迹误差相对于本车已记录贝塞尔参考复算，具有参考的区间必须实际提供误差样本。案例任务目标由评估器读取，不传给策略。

每次尝试独立保存源码/配置/输入快照、命令、参数、初态、完整控制输入与记忆、动作、子步、SUMO读回、原始警告和证据哈希。默认每10个控制区间及最后区间做四类信息反事实决策；传感器历史每步均重建。报告实际比较次数，不宣称每一步都运行四组反事实。

阶段4使用单独的初态安装器，按冻结初态映射的原生道路位置插入车辆，再安装规定横向偏移、航向和速度。两次初始化推进均排除在物理区间之外，只有完整读回后才开始驾驶。外部SUMO载体明确登记 `sumo_external_min_gap_m=0 m`，使2 m车身净距队列能按预定位置插入；NOA跟驰距离与车身裕量不变。真实碰撞检测与失败终止保留，原阶段3安装器及首次初始化失败不改写，详见 `phase4_bootstrap_diagnosis.md` 与独立审查。

`phase4-replay`从冻结初态与参数重建控制器、记忆和积分轨迹，逐字段核对保存输入与输出；同时重算反事实审计和细化轨迹，拒绝观测、记忆、动作、初态、子步、决策、时刻、读回与截断篡改。SUMO不在数值重放时重启，原始读回用于同步一致性检查。若真实运行因碰撞在完整物理区间末停止，则只重建已记录前缀，保留原失败原因和驾驶失败状态。

新增失败边界元数据分别登记已完成控制区间、已完整积分区间、trace行数、部分末记录、隔离审计前缀，以及失败阶段/车辆。重放只计算实际已取得的输入、决策、动作、积分及诊断；不会为故障后尚未执行的车辆补造结果。部分SUMO读回保留已读、读回异常与尚未读取三类状态，预提交读回核对初态、后提交读回核对积分终态。诊断只计算一次并保存，避免在冗余遍历中中断后边界与内容矛盾。

KeyboardInterrupt在已登记案例目录及已有证据收尾、失败统计/状态与哈希落盘后继续抛出，进程仍以失败退出。中断前未进行的故障注入明确标为未执行，数值重放通过不放行驾驶门槛。原先未记录新边界字段的历史部分失败文件不事后添加数据或改写；其原有不可重放限制仍保留。哈希用于检验保存文件是否变化，不是对恶意同时改写全部文件和哈希清单的密码学认证。

首轮离线案例中“merge_no_gap”的两个静止车辆实际允许绕过车列，原运行和失败断言保留；最终协议把它独立命名为 `merge_gap_after_queue`，另增加连续队列的 `merge_no_gap`，每辆4 m车间仅留2 m空间并延伸至终止点之后。此修订纠正工况定义，不改变原结果或放宽安全门槛。
