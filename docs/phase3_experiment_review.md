## 实验层发现及闭环

本轮另复现了两个初始化证据缺口，并在实现方修正后重新验证：

1. **初始化读回原始证据缺失。** 原实现只在 `FleetBridge` 成功构造后写 `bootstrap.json`；b 的初态读回失败会丢失 a 的已通过报告及 b 的原始失败报告。现改为逐车保存初始化报告并随异常传出，`bootstrap.json` 保留初始化阶段、已完成初始化步数、a 的通过报告、b 的失败原始值及 c 的尚未读取状态。故意令 b 的 SUMO `front_x_m=999` 后，该数值完整保留，运行失败且只关闭一次连接。
2. **模型初始化前缺少复现快照。** 原实现的模型构造异常只留下 purpose/run_id 和 traceback。现先登记命令、Python、源码/配置哈希及副本，再构造模型。故意让模型初始化抛异常后，独立失败目录保留 55 个文件及初始化状态；源码/配置原文件可以追溯。

原始失败证据在 `tmp/phase3_experiment_review_e147d689/review_evidence.json`，修正后对应证据在 `tmp/phase3_experiment_review_76a39040/review_evidence.json`。原始失败目录未覆盖。复现脚本是 `tmp/phase3_experiment_review_probe.py`。

## 运行与重放审查

- SUMO 的两步初始化明确位于物理 t=0 前，预设初态的安装与车辆入口/协作调度区分。每物理区间仍是全部终态排队后推进一次；后续观测依赖 Python 共同物理状态，SUMO 读回只能验证，不能改写动作或修补状态。
- 普通案例包括局部跟随、跨 edge、前后目标进入范围及连续横向初态。它们没有伪装成完整自主换道测试。独立几何评估包含车身扫掠碰撞、越界与线性轮胎适用范围，结果仅进入评估；检测失败不回传测试策略。
- `replay_case` 从初态重建传感器、每车有限历史、完整控制输入、动作、连续模型全部子步和诊断，并对整个记录结构比较。真实 SUMO 读回根据保存的原始位置、速度、时间等重新核验，而不是信任存储的 `passed`。离散 track ID 现在按整数和值严格核验，物理量使用明确数值容差。
- `replay_isolation` 为各车和各类反事实单独维护传感器历史，逐条重跑保存的 ID/顺序、隐藏类型、未来计划及范围外状态变换，并检查行数、顺序、当前输入和历史。正向敏感性检查移除可见邻车时保留实际自车/本地历史，防止以恒定策略得到空洞不变性。
- 积分减半使用同一组保存命令；同步/感知减半重新运行闭环。二者含义明确，比较同一物理时刻的位置与航向，未声称边界进入事件必须逐帧完全一致。
- 新增的故障模块保存八类篡改轨迹及一个故意车身重叠的物理失败；正常案例、负例检测与驾驶成功分开。重叠案例只由离线几何判定失败，不调整动作消除碰撞。
