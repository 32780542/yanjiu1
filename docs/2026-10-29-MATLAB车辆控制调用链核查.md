## 2. 主入口的目标速度与实际执行

### 2.1 从实测状态到联合分配

`mainmain.m:418–450` 每步读取全体车辆真实 ID、位置、方向、速度；第457–555行读取真实车型、排除退化/短暂不安全车辆，再按纵向位置和车型字符分组。相邻规则是“距组首不足50米 **或** 距前一车不足25米”，因此组的总长可以超过50米。这不是各车仅用前200/后100米形成的私有观测。

第599–665行每5秒为各组重新生成 `vehicleSpeedList` 和 `vehicleChangeLaneList`，记录 `controlFirstStep`。第637行还用相邻两组边界距离与 `1.3×gap` 比较，可能设 `slowFlag=1`。`formationControl.m:7` 设置 `gap=15`，第37–38行把全组坐标量化成纵向15米格点和车道格点。

`formationControlNormal.m:82–84` 的链为：

```text
全组 coordinatesRelative + 全组 targets
 → getRelativeDistance 的全体代价矩阵
 → assign / assignz / assignln 联合一对一分配
 → pathRelativeCalculate 分段相对移动
 → coordinateMap 的全组离散同格冲突检查/插入等待
 → 每车 singleVehicleCalculate
```

`getRelativeDistance.m:12` 的加权距离计算立即被第13行覆盖，实际生效的代价为 `deltaX² + deltaY²`。不能按前一行描述为加权对角运动代价。

### 2.2 优化器输出是什么

`singleVehicleCalculate.m:16–17` 给每阶段固定5秒的移动目标：

`x_next = x_previous + vF×T − relativeMoveX×15`。

忽略首阶段格点取整偏差和曲线长度，`relativeMoveX=-1` 表示相对前移，要求5秒走159米，平均31.8 m/s；`relativeMoveX=+1` 则走129米，平均25.8 m/s。因此高于28.8的追赶是算法允许的运动，不只是变量命名问题。几何换道曲线也可能增加路径长度。

第63–66行给出 `a∈[-10,5] m/s²`、`v∈[0,33.33] m/s`。单阶段或最后阶段的末速被设为 `vF=28.8`，但**末速等于28.8不意味着全过程不超过28.8**。`BrysonDenhamContinuous.m:10–14` 使用 `s_dot=v`、`v_dot=u`、`z_dot=u²/2`；`BrysonDenhamEvents.m:21–27` 累加各阶段加速度平方积分，并连接阶段速度。这里没有把行程时间作为自由变量最小化；阶段时间已经固定。

`formationControlNormal.m:225–254` 提取优化加速度和速度并插值成0.1秒序列，但第256行只把**第一阶段5秒速度**写入主入口执行列表，第259行也只写第一阶段车道相对变化。主入口随后重新规划。这具有滚动重算的形式，但没有在每步重新优化。

### 2.3 真正送给 TraCI 的是什么

| 情况 | `mainmain.m` 证据 | 实际请求 |
| --- | --- | --- |
| 无速度计划或车辆不在计划中 | 808、853行 | `setSpeed(vehicleID,vF)`，即28.8 |
| 普通 ICV 有非零计划 | 867、890行 | `setSpeed(vehicleID,goalSpeed)`，无28.8截断 |
| 奖励 ICV 有非零计划 | 875–888行 | `goalSpeed + 固定初始误差` 后截到 `[0,vF]` |
| HDV、退化、换道不安全冷却、低速回退 | 774–841、868–870行 | 更改速度/换道模式后跳过或不发新速度命令；不能把此处描述为明确释放旧速度命令 |
| 激进 HDV 加速事件 | 241–254行 | 当前速度再加2–4 m/s后直接 `setSpeed`，没有vF上界 |

第872行对非零计划使用 `setSpeedMode(...,31)`，但源码并没有因此把普通 ICV 请求截到28.8。`New_Edge.m:10–11` 写入道路速度41.66 m/s；`New_Vehicle_frc.m` 的车型写入加减速等参数，却未显式写 `maxSpeed=28.8`。最终实速还由当时的SUMO车辆限速、跟驰和执行决定，**允许高请求不等于已测得每车均超速**。本核查没有实际速度分布，不能给出超28.8时长或它贡献了多少行程收益。

主入口没有调用 `setAcceleration`；优化器的 `akRealSeries` 没有变成加速度命令。其实际速度和事后加速度分别来自 `getSpeed` 与相邻实测速度差（第975–976行），不要混用“优化加速度”和“实际执行加速度”。

### 2.4 轨迹规划不等于轨迹跟踪

`trajectory_planning.m:6–19` 用车辆/目标姿态构造三次Bezier控制点，`PointOnBezier` 返回采样点和曲率，`singleVehicleCalculate.m:43–47` 用采样点累加路径长度。`formationControlNormal.m:204、209、223` 创建 `totalPointListSet`、`closestPosition` 并存路径，但主入口没有读取这些点或最近点索引来控制方向、位置或横摆。

主入口第893–950行在规划起始步向SUMO发 `changeLane(targetLane,2)`；奖励车辆先等0.4/0.5/0.6秒反应时间，届时再检查安全和发换道命令（第168–191行）。所以这是“优化纵向速度序列 + SUMO原生换道”，不是完整的Bezier闭环跟踪执行器；5秒规划阶段与2秒换道请求也不是同一时间量。

## 3. 其他车辆控制文件说明了什么

`One_Vehicle_Control.m:22–69` 是位置误差/误差差分反馈：分段调整 `kp/kv`，算出 `goal_Acc` 后用 `vehicleSpeed+goal_Acc/10` 请求速度，仅截非负；默认目标位置为-1时请求10 m/s。这里没有28.8上界，但其交叉口坐标和调用入口与 `mainmain` 不同，不能用来解释主入口成绩。

`One_Lane_Control.m:41–43` 为HDV/退化车调用OVM；第84、197–205行的信号灯/MPC链生成并插值速度，第92行直接 `setSpeed(control_speed)`。第93行的 `CAV_control` 被注释。该旧链还引用本目录未找到的 `MPC_Main`，不在本次主链求解范围。

`CAV_control.m:16–20` 若由其他代码调用，会将输入加速度用步长积分成下一速度，再 `setSpeed`，函数自身没有速度上界。`Car_following_model.m:29–36` 则把OVM/IDM下一速度积分成坐标，经 `moveToXY` 执行，`setSpeed` 反而注释；其第27行读取的“前车速度”实际使用本车ID，且前车由ID后缀减一构造（`getPrecedingVehicleID.m:3`）。这些历史假设都不适合移植到禁止真实ID顺序的分布式系统。

`applySmoothSpeedControl.m:10–26` 限加速度为+1.5、制动为-2.5 m/s²，再 `setSpeed`，没有vF上界。它声明全局 `simulation_step`，主入口的 `simulation_step` 却不是该全局声明；而且没有调用，因此不能据它宣称当前主入口已平滑。函数注释引用文献不等于已经核实该文献给出了这组参数，本核查不扩张该引用。

## 4. 瓶颈安排如何尝试减少冲突

`formationControl.m:50–54` 以组首是否达到 `X2−vF×T×2.5=640` 米决定三道或两道目标。它提前360米开始两道重排，给横向迁移和纵向错位留时间。`formationControlNormal.m:21–60` 生成同道30米间隔、相邻道15米错位的目标；不是所有车都在同一纵向断面争用同一合流空隙。

之后的联合分配尽量减少全组格点位移，离散路径在同一阶段若落到同一格点，会延后后一个索引车辆（第110–178行）。这有助于减少被模型表示出来的目标占用冲突，但它检查的是**离散同格冲突**，不能扩大为连续车身碰撞证明、两车交叉路径证明或鲁棒安全证明。循环在较后阶段还允许 `breakFlag` 退出，不应把它写成完整CBS安全证明。

主入口实际换道安全门是 `isLaneChangeSafe`（第1054–1092行），扫描全体车辆后调用 `isLaneChangeGapSafe`，要求目标道所有车的绝对纵向车头位置差至少8米；同道请求直接判安全。这个门没有显式检查相对速度、TTC、车长净距、横向占用或预测到达，因此当前项目已有的横向走廊和1秒预测应保留，不能退回成仅8米静态间距。

换道失败把车辆排除编队2秒并切回原生模式（第104–105、908–910、943–945行）；HDV靠近15米退化、超过20米恢复的滞回也会暂停组织。但后者直接读取车型真值并扫描全体车辆，不符合本项目纯局部无车型真值约束，只能借鉴“物理风险触发退出/恢复”的形式。

道路生成还有一个需保留的区别：`New_Edge.m` 两段都写 `numLanes=3`，而 `New_Connections.m:19–21` 仅连接 `0→0、1→1、2→1`。因此这是三道入口争用两条连接的瓶颈；不能未经核对已生成网络，就把它说成整个1000–1200米都只有两条实体车道。本项目运行器的两道下游属于其自身场景定义。

## 5. 局部前200米/后100米可借鉴的最少规则

以下是从代码机制推导的工程建议，**尚不是已经验证有效的新增算法**。不需要恢复全局目标表、通信或车型真值。

| 机制 | 可在局部感知中保留/实现 | 不可原样移植的部分 |
| --- | --- | --- |
| 提前准备瓶颈 | 用本车地图位置判断准备区；终止道提前找真实前后车空隙；准备区不再自由补入终止道 | 组首触发所有成员同步转两道、中心给所有车换位 |
| 交错和留隙 | 保留本车对真实同道前车跟驰及局部跨道错位；横移前后以目标走廊内真实前后车约束 | 全组统一基准、所有目标槽位、一对一联合分配 |
| 冲突抑制 | 自由补位让必要合流；在本车可见冲突走廊内延后动作；保留当前实际空隙边界和冷却 | 全局 `coordinateMap`、遍历全车队索引决定谁先、隐藏共享排程 |
| 拥挤退出与恢复 | 本车/可见邻车低速、逼近或安全门失败后暂停非必要横移，恢复时用滞回避免频繁切换 | 读取HDV/ICV类型、全网最小速度、按真实ID排序或授权 |
| 平稳速度 | 用当前实速阻尼、统一物理执行及共同安全裁剪；位置修正不得绕过共同巡航上界 | 把优化轨迹允许33.33直接当作瓶颈收益 |

对 D 版的最小优先级建议是：

1. **先去除归因混杂**：NOA和编队/变换都用28.8 m/s共同硬上限，运行器车辆上限、控制请求和安全上限保持一致；使用相同请求序列、初速、车型和原生插入。此步是公平实验约束，不是宣称已找到性能最优参数。
2. **保持现有必要合流与安全链**：当前 `_merge_target` 跟真实F/R空隙、`_clear` 的横向走廊及1秒预测、必要合流优先规则已覆盖了可局部化的主要思想。不要为复刻MATLAB而加入新的中央分配层。
3. **只有瓶颈证据显示必要时再改一条组织规则**：例如低速/拥挤时暂停非必要补位，并在恢复后再允许；用已有自身记忆做短滞回。每次只改一个能说明反例的规则，完整保留无改善结果，不把改规则和放宽最高速度混在同一批里。

本次读取的D版为[冻结native_rules.py](experiments/2026-10-29-four-flow-attribution/portable_D_baseline/source/noa/native_rules.py)：`CRUISE=28.8`、`MAX_SPEED=33.3`；`_request` 允许33.3，跨道相位速度为28.8±2。NOA通常请求28.8，必要合流也调用 `_request`，所以不是“只有编队绝对能超速”，但两者自由流超28.8机会明显不一致。运行器 `native_sumo.py:40` 同样设置33.3车辆上限。该观察冻结于证据JSON所列哈希；后续更新不得反向套用此版本的结论。

## 6. 四流量如何证明瓶颈更不拥挤

`mainmain.m` 虽有多次 `Tflow` 赋值，第37行最终覆盖为0.042；0.1秒步长且每道独立一次伯努利请求时，其期望是1512辆/(道·小时)。历史数组0.014/0.021/0.028/0.042对应约504/756/1008/1512，不能冒充精确500/750/1000/1500。本项目应明确四个流量单位为每道每小时，按 `p=q×0.1/3600` 生成请求，并在同种子配对中冻结完整请求账本。

每个流量同时比较直路和3→2；全车完成、未完成、安全失败均进入总表。共同限速后，瓶颈归因至少需要以下几组可复算证据：

- 速度公平：目标请求与实测速度的最大值、超28.8时长/距离；两个模式应满足共同上界。自由直路差异另列，不能只报3→2行程时间。
- 局部拥挤：固定瓶颈窗口内低速车辆数和低速车秒、最大/平均低速队列长度、占用车辆数随时间；使用同一阈值与窗口，并同时列替代阈值或保留轨迹便于复算。占用变低本身也可能来自吞吐下降，要与完成数和流出率一起看。
- 瓶颈损失：逐车或同种子计算同一测量区间的额外行驶时间，比较“3→2减直路”的损失；这比单独总TT更接近瓶颈增量。位置穿越用相邻轨迹插值，未穿越者保留删失/未完成。
- 冲突过程：终止道换道开始/居中完成位置、最后时刻合流数、目标道制动/停车、换道安全门受阻次数、合流流出时距。换道车数本身不是收益。
- 系统完成：请求、插入、离场、入口等待、在网余车、最终排空时间，避免把入口阻塞或未完成车辆隐藏到平均值之外。

只有在统一限速、同需求、安全和完成条件均成立，且瓶颈低速车秒/队列或瓶颈增量损失确实下降时，才能说结果“支持收益来自瓶颈更不拥挤”。若只有行程时间下降，或直路同样下降，或队列指标未改善，应明确写“尚未证明瓶颈减拥挤”；不补造集中方案效率、原论文标量或MATLAB运行值。

`mainmain_REF.m:66` 使用30 m/s，车型生成 `New_Vehicle.m:9` 是加速3、tau0.45；主入口普通ICV为加速5、tau0.2。该历史非编队参考既不同速也不同车型，不能用作本次纯NOA的公平对照。`mainmain_REF_3` 还存在直接33.3的跟随车请求，但它是另一历史算法；不能把这些分支拼成一套已验证的统一方法。
