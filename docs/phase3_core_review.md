## 已验证的正确行为

- `ControlInput` 由不可变自车、局部观测及历史记录构成；正常构造路径采用 tuple，不携带真实键、隐藏类型、计划、全局槽位或他车记忆。测试策略只读取传入输入与一组策略/车身参数，不读取 TraCI、文件或真值表；未使用 track ID、绝对位置或物理时间决定优先级。
- 帧对全车时刻、真值有限性及键唯一性先行检查。矩形筛选依据二维 CG 位置，不依赖 edge/lane、不做遮挡过滤；速度转换为世界相对速度后表达在自车坐标中。
- 本地编号只依据允许测量字段分配新编号；退出即清除当前键关联，重入获得新编号。不可区分的重复测量组不维持隐藏键关联。历史记录保留已有观测，过期后删去，不查询范围外目标补齐历史。
- 时钟先生成全部输入，再生成全部动作、积分全部车辆。批量桥在全部积分校验及提交前读回检查后，排队全部终态，并且每区间只调用一次 `simulationStep()`。同步失败后，桥和时钟均停止，不继续推进、不调整动作补救。
- 两份现有测试共 13 项全部通过。另进行了 50 帧完整输入、历史及动作相等检查：一致地重命名真实键、逐帧改变隐藏类型/计划、加入并改变范围外车辆并打乱帧顺序，包含退出/重入及完全不可区分测量组，全部相等。

## P2：旋转后的包含边界会被浮点舍入排除

位置：`perception/ideal.py:76–78`、`perception/road.py:11–15,21–31`。

`ego_point` 的三角变换结果直接进入严格不等式范围判断；道路线段也采用相同变换后严格裁剪。名义上在范围边界的实体会因正常双精度舍入被排除，而现有测试只在零航向测试四边包含，旋转测试的目标都在内部。

可复现输入：自车 CG `(300, 10)`，航向 `math.pi/2`；邻车 CG `(250, 210)`。物理构造的自车坐标是 `(200, 50)`，实际计算得到 `(200.0, 50.000000000000014)`，当前输出 **0 个邻车**。将道路边界设为世界线段 `(250, 200) → (250, 210)`，其名义局部范围是 `(190, 50) → (200, 50)`；当前道路观测为空，整段侧边界消失。

影响：违背“边界计入范围”和车辆/道路边界规则一致的验收意图；目标恰在边界时还可能被误判退出，随后重入产生新的 track ID。此问题发生在机器舍入量级，不是 10⁻⁶ m 等实际范围外目标应被纳入的理由。

建议：明确共同的数值边界政策，按照坐标变换误差处理近边界值，并让车辆筛选与道路裁剪使用同一政策；不要用任意大容差扩大有效感知范围。补测前后左右各边、四角、90° 与普通非零航向，并保留明确位于边外的排除测试。检查临界时刻 track ID 不因纯旋转舍入发生退出/重入。

## P2：失败区间会记录上一区间通过的读回，丢失实际失败证据

位置：`simulation/multi_vehicle.py:32–34,43–45,94–98`。

同步前执行 `b._require(b.readback())` 时没有把新报告保存到 `last_reports`。同步后用字典推导式收集读回，任一车读取抛异常时整个赋值不发生。两种路径均使 `last_reports` 保留空字典或上一区间数据；时钟异常处理随后把它原样写入当前失败区间的 `readback`。异常字符串能表明失败，但错误车辆、原始值及已取得的当前报告丢失，已有记录还会呈现过期的 `passed=True`。

可复现路径 A：使用现有测试的假连接完成一次同步，SUMO 时间约 0.3 s；额外增加原生时间到 0.4 s，再 tick。抛出 `SUMO time readback mismatch: 0.1`，但失败记录中的 a/b/c 读回时间全部仍为约 0.3 s、`passed=True`。异常对象的 `report` 含实际 0.4 s 失败报告，时钟未保存它。确认未额外提交或推进，桥和时钟都已终止。

可复现路径 B：一次成功区间后，在下一次 SUMO 步结束时让 b 的 `getPosition` 抛出“车辆消失”异常。a 的当前读回已经成功获取，但因推导式中断同样丢失；失败记录中的 a/b/c 仍是上一区间约 0.3 s 的通过报告，实际 SUMO 已到 0.4 s。

影响：损害阶段 3 要求的失败运行可审计性，并容易使后续日志/重放把旧读回错误地归属于本区间。这是证据保存问题，不是发现了自动恢复、重试或控制补救。

建议：每次同步建立新的尝试记录，分别标注提交前/提交后的报告，按车逐项保存读回及读取异常；保存失败报告与已经取得的报告，不能借用上一区间的报告填充缺项。允许在不推进、不更改命令的前提下继续采集其余车辆的诊断。为原生额外步、提交中异常、部分车读回异常和第二次区间失败分别断言时间归属、缺失原因、完整证据及禁止重试。

## P3：无效遍历顺序的失败语义未明确

位置：`simulation/multi_vehicle.py:77–80`。

`tick(order=('a','b'))` 对三车时钟抛出 ValueError，但检查发生在失败记录边界之前，结果为 `failed=False`、`last_record=None`，再次有效 tick 可以成功。该调用没有生成输入、积分或推进，因而它与“部分区间失败后禁止恢复”并不等价；本项不作为隐藏补救的证据。

建议在接口/报告中明确：这是区间开始前的调用参数校验，还是必须记录并终止的运行尝试。若整次尝试均要求保留，调用层需要保存此错误；若允许调用者改正参数，文档应缩小“任何失败均终止”的表述，并增加对应测试。
