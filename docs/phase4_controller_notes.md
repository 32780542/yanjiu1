# 阶段4纯局部NOA控制器说明

本实现是用于有限范围理想观测小案例的通用开发基线，不是品牌NOA标定、完整论文复现或严格安全控制证明。控制器只接收当前 `ControlInput`、本车有限观测历史及冻结参数；返回动作、本车新记忆和可JSON编码的诊断。真实SUMO运行、独立真值审计和数值重放由阶段4外部实验层完成，控制器单元测试通过不代表M1验收通过。

## 文件与接口

- `noa/contracts.py`：不可变、slots的 `NoaMemory(LocalMemory)` 和 `NoaDecision`；`memory_from_dict` 复原 asdict/JSON 记录。
- `noa/road.py`：用本车位姿将当前可见边界和标线转换为世界坐标，重建局部直路横截面、相邻中心及真实收窄边界。观察框裁剪端点不会被当成物理车道终止。
- `noa/prediction.py`：观测邻车物理量、限幅横向跟踪、纵向可达包络和候选全区间车身扫掠检查。
- `noa/controller.py`：纯函数 `decide(control, parameters) -> NoaDecision`，无文件读取、TraCI、全局车辆列表、车型真值或共享计划。
- `configs/phase4.json`：全部新增NOA策略参数及来源、单位、状态、理由。实验时长和脚本工况由外部配置独立冻结。
- `tests/test_phase4_controller.py`：局部行为、几何不变性、连续积分、候选拒绝、停车和信息入口测试。

`NoaMemory((), 'CRUISE')` 可直接初始化。新增字段是本车 `plan`、`target_y_m`、`prepare_since_s`、`lane_change_reason`、`last_lc_end_s`、`completed_lane_changes`。其中 `plan` 直接使用现有 `QuadraticLaneChange` 的五个字段：`start_s/y_start_m/y_target_m/duration_s/speed_mps`。参考属于本车，保留到实际完成；到期后参考继续保持目标中心以完成跟踪，不跳变到参考点。观测历史由时钟在每次采样时替换为传感器已有的1秒历史。既有 `LocalMemory` 及阶段3序列化字段未修改。

## 控制与状态

状态包括 `CRUISE/FOLLOW/PREPARE_LC/EXECUTE_LC/MERGE/EMERGENCY`。纵向将速度误差、净间隙、相对速度、时间间距和含控制/执行器/jerk响应余量的停车距离筛选结合。停车距离用jerk过渡积分及较弱的恒定制动尾段作保守开发近似。观测到正在横向切入的邻车会在实际同车道重叠之前影响制动。低速接近静止前车时给出有限小制动，避免纯比例跟驰仅渐近收敛、持续爬行。前车可见运动恢复或退出当前局部间隙后允许起步。

物理车道终止被当作静止虚拟停车目标，持续使用间隙和相对速度反馈，而不是停车距离阈值一旦解除就恢复巡航。缺少空隙时可减速停车；有足够空间的候选仍需经过准备和重新检查。不存在固定的1000米/640米坐标触发、laneIndex或目标车道真值注入。候选只来自当前中心的相邻可见中心；慢前车驱动超车，局部收窄驱动并道，完成后的冷却结束后可由新观测再次触发换道。几何对称候选按正世界y方向偏好排序，不采用邻车编号裁决。

横向使用现有两段二次贝塞尔C1参考，加位置/横向速度反馈形成等效转向命令；既有运动学积分、转向响应、硬界、舒适性及jerk设置保持不变。动作不会直接改写位置、速度或航向。

## 候选预测假设与边界

每次候选检查覆盖剩余参考时长及0.5秒稳定尾段。最长预测命令片段0.1秒，每段用现有 `KinematicModel` 以不大于已有 `max_dynamics_dt_s` 的子步推进；各子步执行车身与道路、车身与邻车可达占用的保守扫掠。车身各侧加0.15米几何裕量；未收敛的扫掠叶节点按潜在冲突拒绝。预测区间越出当前已观察到的道路也拒绝。

邻车纵向包络包含继承的全部硬加速度范围（−10至5 m/s²）及速度截断（0至33.3 m/s），不假设他车让行、制动或维持控制计划。每个时间片考虑加速度曲线相对线性插值的弓高余量。横向采用当前观测的惯性横向速度和固定观测航向；登记的额外横向加速度界为0，这是明确的有限预测假设。它不保证应对未来突然开始、当前尚无运动迹象的横向动作。

本车预测暂按当前纵向请求保持及同一横向参考推进，因此结果以该未来请求假设为条件。下一实际控制周期会从新观测重新计算并检查，不能将一次通过解释为任意未来动作下的安全证书。扫掠检查证明的是所采样运动学子步之间的线性位姿插值模型；不是任意连续非线性轨迹的形式化证明。

速度上界处的实际加速度0可能遮蔽仍为正的本车执行器状态。此时停车筛选使用继承 `max_accel_mps2` 作为保守执行器上界，候选预测直接报告 `own_actuator_unobservable_at_speed_cap` 并拒绝，直到执行器状态可从实际加速度恢复观察。该上界以初始执行器处于已有硬界内为前提。停车边界处实际加速度0也可能遮蔽负执行器状态，候选预测同样报告 `own_actuator_unobservable_at_stop` 并拒绝，不假定执行器立即复零。新换道本来还受5 m/s最低起始速度约束；上述停车检查尤其保护执行中已停下的本车参考。

执行中若预测失效，控制器保持原本车参考并制动，报告 `EMERGENCY`；不突然切换相反方向，也不将轨迹吸附到车道中心。这种处理保证没有状态跳变，但不是一般最小风险停车或安全回撤规划。突发阻塞、双方同时换道、不可避免的近距切入和严重急刹可能仍发生碰撞、越界或舒适性失败，必须由外部审计保留。参考未完成时可继续保留用于恢复跟踪，不保证在任意环境下最终完成。

只支持当前传感器和道路契约中的相邻、直线、世界x方向道路。斜道路、反向交通和不完整边界不在当前支持域，异常或不足几何会拒绝输入。除自身计划外不持有其他车的未来状态；不在观察范围之外更新邻车。邻车编号和输入顺序不参与控制优先级。

## 参数与开发证据

新增参数使用 `noa_` 前缀，来源均在 `configs/phase4.json` 标为本研究未标定开发设置。默认目标速度20 m/s、准备0.5秒、参考5秒、完成冷却1秒、名义跟驰间距3米+1.8秒速度项；增益与预测边界在同一配置逐项登记。开发发现渐近爬行后增加低速停车触发速度1 m/s、静止队列净间隙12米及制动0.5 m/s²三个参数。它们允许实际停止时保留更大净空，不调整已有硬界或舒适性阈值，不保证实际停车jerk达标。

开发日志位于 `results/phase4/controller_dev/`，所有失败保留：

- `01`：11项测试在缺少控制器时失败；`02`：首实现因过度停车距离近似导致三项候选测试失败；`03`：11项通过。
- `04`：非法物理界及负几何裕量未拒绝；`05`：补充验证后16项通过。
- `06/07`：静止前车渐近爬行及“两辆静止车等于全程无空隙”的错误测试预期。两辆稀疏静止车之后确实存在合法并道通路，未为了满足错误预期改变策略。
- `08/09`：换为真正密集队列后暴露道路端点停车再起步缺陷，扩展轨迹记录显示越界；`10`：虚拟停车目标修正后21项通过，包括20秒阻塞停车。
- `11/12`：速度上界不可观察执行器的失败及修正后23项通过。
- `13/14`：停车边界不可观察执行器的失败及最终控制器套件验证。

最终套件包含24项，覆盖普通换道/并道实际连续积分、车身道路占用、20秒密集队列停车、静止前车停车再起步、全时域目标车道终止和高速后车拒绝、执行中新阻塞保留原参考、横向切入反应、道路平移、视域外道路不触发、局部ID和顺序不变性、JSON往返、硬加速度可达包络、非有限输入拒绝及政策源码信息入口检查。此处只报告控制器层验证；全案例驾驶、舒适性、采样敏感性和阶段4是否验收由独立实验结果决定，不能据这些单元测试宣称消除了已记录的切入舒适性或严重急刹压力失败。
